## 三、已修复缺陷

### D-01 `MV` 指令解析 panic（P1 · 安全性 · 已修复）

- **位置**：`crates/host-core/src/tools/hashline/parse.rs` · `parse_dest`
- **证据**：原实现
  ```rust
  if (raw.starts_with('"') && raw.ends_with('"')) || (raw.starts_with('\'') && raw.ends_with('\'')) {
      raw[1..raw.len() - 1].to_string()
  ```
- **成因**：单个引号字符 `"` 同时满足 `starts_with` 与 `ends_with`，`len()` 为 1，切片 `raw[1..0]` 使索引下界大于上界 → panic。
- **触发条件**：模型在 `MV "` 这类畸形参数下即可触发。该函数运行在**特权宿主进程**中，一次 panic 会让整个文件系统与数据库层不可用。
- **修复**：增加 `len() >= 2` 成对判定；单个引号按"去引号后为空"处理，归一为 `EDIT_PARSE_FAILED`。
- **验证**：新增回归测试 `rejects_a_lone_quote_instead_of_panicking`，覆盖 `"`、`'`、成对引号、裸路径四种输入。

### D-02 Windows 依赖安装器误用 shell（P1 · 功能 + 安全 · 已修复）

- **位置**：`apps/desktop/electron/main/npm-installer.ts` · `defaultDependencyRunner`
- **证据**：原实现
  ```ts
  const child = spawn(command, args, { shell: process.platform === "win32", ... });
  ```
- **成因**：Windows 上对**所有**命令启用 shell，而 shell 只对 `npm.cmd` 这类 shim 有必要。后果有两个：
  1. **功能失效**：真实可执行文件路径含空格（`C:\Program Files\nodejs\node.exe`）被 `cmd.exe` 按空格拆断，命令直接失败。
  2. **命令注入面**：`args` 会被 `cmd.exe` 重新解析，插件 `package.json` 中的依赖名/路径若含 `&`、`|`、`(`、`)` 等元字符，即可越出"安装依赖"这一语义。
- **修复**：只对 `.cmd`/`.bat` 启用的 shim 使用 shell，其余走 `shell: false`；shim 分支对参数做 cmd 转义；`npm` 这类裸命令名在 Windows 上补全 `.cmd` 后缀。
- **验证**：原先在 Windows 上必失败的两个用例（`default runner caps captured stderr`、`default dependency runner isolates npm config sources`）现均通过。

### D-03 插件访问未注册绝对路径的错误码语义（P2 · 契约一致性 · 已修复）

- **位置**：`apps/desktop/electron/main/plugin-runtime.ts` · `resolveFsRequest`
- **现象**：插件对"项目从未注册的文件夹"发起绝对路径访问，返回 `INVALID_ARGUMENT / path escapes the plugin's root`；而同一文件的既有注释明确写着"告诉作者自己试图逃逸是谎言"。
- **影响**：同一份代码里存在两种拒绝哲学。对合法插件作者而言，错误提示指向了错误的原因，排障成本转移给了生态开发者。
- **修复**：相对路径越界仍报"逃逸"（作者确实写错了）；未注册的绝对路径按"从插件视角不存在"报 `NOT_FOUND`，同时不泄漏"该路径在磁盘上是否存在"。
- **验证**：`plugin-fs-scope.test.mjs` 25 个用例：24 通过 / 1 跳过（符号链接需平台权限），0 失败。

### D-04 ~ D-07 测试跨平台健壮性（P3 · 工程可信度 · 已修复）

| 编号 | 位置 | 问题 | 修复 |
|---|---|---|---|
| D-04 | `packages/agent-runtime/src/native-pi-session.test.ts` | 用 `split("/")` 取文件名，Windows 反斜杠下返回整个绝对路径 | 改用 `path.basename` |
| D-05 | `apps/desktop/test/plugin-fs-scope.test.mjs` | 符号链接创建在无开发者模式的 Windows 上抛 `EPERM`，使安全测试整体报错 | 捕获 `EPERM`/`EACCES` 并以 `t.skip` 标记 |
| D-06 | `apps/desktop/test/macos-release-verification.test.mjs`、`packaging-footprint.test.mjs` | macOS 专用脚本测试在 Windows 上调用 `wsl.exe` 失败；POSIX 可执行位在 NTFS 上不可表达 | 非 darwin 平台跳过脚本用例；可执行位断言加平台条件 |
| D-07 | `apps/desktop/test/logger-routing.test.mjs` | 日志脱敏结果保留原生分隔符，断言写死 `/` | 断言前归一化分隔符 |

> 这四条不是产品功能缺陷，但它们让"Windows 上永远有红灯"成为常态，真实缺陷会被淹没在噪声里。修完后 Windows 侧测试可信。

## 四、待修复缺陷

以下为静态审计发现，优先级按"用户可感知程度 × 修复成本"排序。**未标注"已验证"的条目为静态推断，落地前需先复现。**

### 4.1 P1

| 编号 | 位置 | 问题 | 建议 |
|---|---|---|---|
| O-01 | `crates/host-core`（全 crate） | `spawn_blocking` 使用数为 **0**。SQLite 查询、文件读写、目录遍历等阻塞调用直接在异步任务里执行，会在慢盘/大仓库场景下占死 RPC 工作线程，表现为界面"整体卡住"而非单请求超时 | 在 RPC 分发边界引入阻塞任务池，按方法白名单迁移；优先迁移文件写入、全量搜索、会话列表三种调用 |
| O-02 | `apps/desktop/electron/main/ipc/agent-ipc.ts:254` | `native-pi:` 会话在 `acquireSessionOperation` 之前直接分流，绕过同会话互斥；非 native 分支才加锁 | 先确认运行时内部是否已串行化同一会话的 `agent.prompt`；若没有，需为该分支补同一把锁，否则并发提交会交错写会话日志 |

### 5.3 差距判读

1. **不要在办公套件上正面竞争**。WorkBuddy 的护城河是"产出物 + 生态"，追平需要文档引擎、模板体系、连接器三件套，投入大且不占优势。
2. **本项目的护城河是"过程可控"**。Plan 模式、权限闸门、审计留痕、插件隔离——这些是办公类产品普遍偏弱的地方，也是企业采购时最容易被追问的地方。
3. **会议纪要是正确的切入点**。它同时满足三件事：WorkBuddy 有（说明有需求）、本项目能做（Rust 生成 docx 已在规格中定案）、本地化是差异（音频不出本机）。它是"进入办公交付物"的最低成本入口，而不是终点。

## 六、优化建议

### 6.1 近期（1–2 周，低风险高收益）

| 项 | 动作 | 收益 |
|---|---|---|
| O-01 前半 | 在 RPC 分发边界加阻塞任务池，先迁移 3 个最高频调用 | 大仓库下不再整机卡顿 |
| O-02 | 复现并确认 native-pi 同会话并发写 | 消除会话日志交错风险 |
| O-03 | handler 隔离 | 单个订阅者故障不再放大 |
| O-04 | 外链拒绝记审计 | "点了没反应"可排查 |
| O-06 | 补 PR / 定时任务文档 | 功能可被发现 |

### 6.2 中期（1–2 月，能力补齐）

1. **统一三条契约**：会话互斥（所有模式同一把锁）、错误码（拒绝 ≠ 不存在 ≠ 越界）、外部打开（白名单 + 审计）。
2. **办公交付物最小集**：先做 docx（会议纪要直接复用），再评估 xlsx。不碰 PPT——投入产出比最差。
3. **会议纪要 M6–M8**：按规格书推进，交付物是"会后 3 分钟出草稿"的可验证指标。

### 6.3 远期（结构性问题）

1. **阻塞 IO 全面迁移**，并加"RPC 单请求超时"作为兜底。
2. **`unwrap` 清零**：非测试模块启用 clippy 告警，作为 CI 门禁。
3. **插件信任模型升级**：当前"用户主动信任 + 进程隔离 + 权限声明"，可评估加入签名与来源白名单。
