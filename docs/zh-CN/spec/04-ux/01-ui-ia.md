## 1. Goal

清晰、克制、开发人员优先的工作台：一个窗口，一个活动
目的地、聊天作为主页表面、工具和权限内联。

  非破坏性 pin/archive 操作，独立的对话分支

  可通过设置 → 项目存档发现。
  可折叠到图标导轨 (Cmd/Ctrl+B)。展开列固定为 275px；历史版本保存的
  可调宽度偏好会被忽略。
- **产品标识**：运行时 shell 复制使用 `PI-Desktop`；主场英雄和
  侧边栏重复使用派生的 `src/assets/brand/logo-*.png` 标记，而输入框提示
  行没有领先的品牌图标，会话创建控件使用专用的
消息加号图标。开
  Windows/Linux，扩展侧边栏以键盘可访问的主页开始
  右侧的品牌和折叠侧边栏控件；激活
  品牌返回主窗格进行聊天。 macOS 扩展侧边栏省略了
  logo/title 品牌，仅将“折叠”侧栏放在右侧
  红绿灯行`Codex` 仅保留外部导入源或
  设计参考术语。
- **主窗格**：一次仅一个目的地；目的地取代
  窗格（它们是页面，而不是模式）。
- **标题栏**：平台本机桌面 Chrome (D118)。 macOS 用途
  `hiddenInset` 交通灯和系统应用程序菜单。扩展后的
  侧边栏将“折叠”侧边栏保持在同一 46 像素行中，并与
  交通灯安全区域外的右侧；没有呈现 logo/title
  那里，包括全屏。当工作面板打开时，会话
  窗格标题栏在右上角托管其折叠控件。面板标题栏改为可横向滚动的标签条，
  后接固定的 `+` 新建入口；关闭操作归属于各标签，因此 Windows 原生关闭
  控件旁不再重复呈现第二个 `×`。工作面板预览模式会卸载 MainChat，
  并在窗口级 46px chrome 行中保留新建任务、侧边栏和本机窗口控件。
  macOS 非全屏且侧边栏折叠时，左侧预留 76px（全屏为 8px），避免与交通灯重叠。
  Windows/Linux 使用无菜单的无框架 46px 行，并在
  左侧和可访问的最小化/最大化或恢复/关闭控件
  右（D129）。目的地历史以快捷键为主（`Cmd/Ctrl+[` 和
  `Cmd/Ctrl+]`），不渲染专门的 back/forward chrome；插件页激活时，页脚
  插件按钮执行一次后退，是它唯一的鼠标入口。主标题栏没有
  通知行动；耐用的本地收件箱从侧边栏页脚打开
  改为响铃 (D130/D117)。
- **工作面板**：由工件打开的停靠右列（不是覆盖层）
  或 `Cmd/Ctrl + J`。文件、URL、浏览器预览和成功的工作区编辑
  工件会自动创建资源。面板可见时，46px 内容标题显示可横向滚动的
  标签条和固定 `+` 入口；`+` 菜单只有一个 Tools & panels 分组，包含
  Review、Artifacts、日志、命令与当前范围内所有插件视图。文件路径保持独立，插件视图按视图引用
  去重。`Cmd/Ctrl + J` 揭示了
  活动会话的保留面板上下文，无需创建资源选项卡；的
  当面板关闭时，创建触发器仍然不可用。一个
  成功的活动会话工作区 Write/Edit 工件打开审核；
  临时写入、失败写入和后台会话写入永远不会抢走焦点。
  拖动通过共享三栏预算调整面板宽度：向左拖动直到 MainChat 到达 450px，
  此时展开的左栏立即让位；向右拖动把空间还回去。手动重开左栏会优先
  占用工作面板宽度，必要时以 460px MainChat 为目标。唯一的面板级控制崩溃
  面板；
  每个会话保留其自己的运行时打开状态、选项卡集、活动选项卡和
  渲染器内存中的浏览器资源。选择另一个会话会交换
  可见面板上下文而不删除任一会话的状态；选择一个
  没有活动对话的工作区隐藏面板而不是
  重新解释相关资源。背景工件仅更新它们的
  原始会话保留的面板上下文，并且永远不会打开、激活或
  调整可见面板的大小。启动关闭，没有保留会话
  上下文，并且只有首选面板宽度在启动时保持不变。命令标签（W-15）按执行顺序列出本会话的 run 工具——命令、stdout、stderr、退出码与耗时。它是对会话记录的一种投影，不是终端：不开通道、不起进程、不接受输入，所以一条命令可以被从头读到尾，但永远不能在这里敲进去。输出过长时从头部裁剪，并在行内写明截掉了多少字，而不是静默丢掉尾巴；每行都能定位回对话里那次调用。
  工作面板是固定客户区的固定宽度流入列
（ADR 0033）。打开它会将 MainChat 回流到左侧并且不会扩展操作系统
  窗户；折叠释放空间和分隔线，关闭最后一个标签时面板保持打开并显示 New 启动器。
  提交更新首选宽度。受限窗口中 MainChat 保持 450px 硬下限，由右栏缩减补齐；
  左栏在阈值处让位，右栏关闭时恢复。本机窗口边缘通过回流调整聊天大小，而不是
  面板。 Maximized/fullscreen 不受影响；在显示器之间移动或更改
  显示工作区通常协调窗口边界。持久基地
  边界是用户的窗口大小。背景工件永远不会改变
  可见面板（D163，ADR 0033）。外层窗口在每个平台上都保留操作系统原生的
  边缘和角落调整大小，最小支持尺寸为 1040×700。原生边界恢复会等待调整
  大小或移动流空闲，最后稳定的基础边界经过短暂去抖后保存，因此慢速拖动不会
  在手势中途被覆盖。
  取代了以前的上下文面板覆盖； workspace/model/status 信息生活
  相反，在输入框芯片和设置中。
  文件面板就地预览文本、Markdown 与图片；`.docx`、`.xlsx`、`.pptx` 打开只读文档视图，
  不再落到二进制空态：Word 在纸张底面上呈现标题、段落与表格，Excel 以首行为表头、
  表格可横向滚动并支持多工作表切换，PowerPoint 按页纵向堆叠 16:9 卡片。
  表格单元格宽度设有上限，超长内容以省略号收尾、悬停可看全文——主进程不提供列宽信息，
  单个宽单元格不应决定整张表的宽度。
  这些文档由主进程解析，渲染端从不把它们当文本读取。解析失败或格式不受支持时，
  回落到普通文件状态，给出原因并提供「用系统应用打开」入口，而不是渲染字节；
  超出预览上限的内容仍会显示，并在顶部标注已截断。
- **输入框**：与工作空间无关的浮动药丸锚定于对话
  目的地 - 在底部保留的输入框上方居中居中的空家庭内容
  (D111/D204/D206)，位于转录本底部，没有项目/本地/分支
  铁路（D095）。
  其左侧输入操作模式芯片是唯一的活动会话控制
  **Agent**、**Plan** 和 **Goal**。 Plan 显示相同 Agent 的规划状态；
  Goal 显示结果合同的相同批准边界。两者都保留
  权限模式芯片并公开其主机写入的不可变 `.pi/plan/*.md`
  或提交后的 `.pi/goal/*.md` 工件开启器。对话顶部栏只保留任务标题和
  窗口操作；Composer 拥有模型、推理和模式选择。
- **后端状态胶囊**：后端出现时出现在标题栏下方
  通过打开日志操作重新启动或严重降级 (D080)。

## 3. 目的地

- 空状态：克制的英雄标题（“我可以帮你建造什么？”——项目会话里项目名称
  变为点下划线按钮，点击展开可搜索的项目切换菜单，列出侧边栏已打开
  项目，并可从语法上的公网远程克隆 Git 仓库（ADR 0247 / D416）或打开本地文件夹），可选的首次运行检查表和底部保留
  输入框。任务输入直接在composer中启动；没有开发人员入门
  渲染卡片或上下文快速操作行 (D204/D206)。检查表与输入框之间可以放一张文件夹说明卡：
  每个文件夹只出现一次，三行说清这个任务写到哪里、读超出该文件夹会先询问、
  以及转录/日志/用量计数只留在本机。尚未绑定文件夹时提供**选择文件夹**，
  另有**知道了**用于关闭；关闭按文件夹记忆。说明卡不构成发送前闸门——
  工具级授权仍是唯一的闸门。
- 带文字记录：消息流 + 工具披露行 (D071)，上下文
  每个成功的工作区后立即显示消息范围的审核卡
  Write/Edit 行、停靠的 Composer 和内嵌的会话范围权限卡。
  该卡读取消息的持久审阅快照而不是当前的
  Git diff，因此在提交后保持可见。它显示文件状态和
  addition/deletion 进行计数，扩展确切的消息块，并且
  提供受保护的回滚；它不是全局成绩单条目。背景
  会话的消息、工具和权限事件永远不会取代或覆盖
  可见的对话。

### 3. 2 侧边栏项目组

- **部分**：紧凑的 `Sessions` 标题位于 `Projects` 之前并拥有
  无路径对话创建加上现有的 sort/archive-view 菜单。其
  工具栏在创建新会话之前进行排序。两个标题都保持沉默
  字形操作，还接受标题或空白上的右键单击创建菜单
  列出 chrome，以便部分创建保持可发现性
  无需额外镀铬。它的列表之前最多显示五个紧凑行（140px）
  内部滚动，因此独立作品保持可见而不会移位
  项目导航。以下 `Projects` 标题公开了
  文件夹选择器操作；保留的项目组使用剩余的高度和
独立滚动。
- **身份**：每个组都由规范化的完整项目路径作为密钥，从不
  通过可能不明确的文件夹基名。
- **标题**：项目名称、活动状态、披露、新任务操作和
  溢出菜单。目录标题是一个整行的披露目标；
  collapse/expand 仅影响子级可见性，相邻组形成一个
  密集的树而不是分离的卡片。悬停或聚焦项目标题
  揭示完整的项目路径。
- **项目操作**：打开文件夹显示项目目录；重命名只修改
  renderer 本地显示名称，规范化路径仍是项目身份；pin/unpin
  更改演示优先级；archive/restore 隐藏或恢复组；close 删除保留的
  选项卡而不删除或归档 project/session 数据。自定义显示名称与侧边栏
  偏好一起保存，重启后在侧边栏和项目存档中继续使用。
- **对话操作**：pin/unpin、archive/restore 和删除保留
  单独的行动。存档永远不会删除文字记录。打开的文件夹是
  项目行动，而不是对话行动。
- **排序**：面向用户的模式为最近更新、创建日期、最旧
  首先是姓名。固定的行先于未固定的行。项目组通过拖动标题
  或在该标题上按 `ArrowUp`/`ArrowDown` 切换到 `manual`。会话 `manual` 仍是兼容性值。
- **对话列表**：每组显示最近的十个会话
  默认情况下活动排序顺序；剩下的折叠在 **再加载 N 个…** 后面
  单击时展开完整时间分组列表的行。固定行位于前面
  未固定的行，并且永远不会被推到折叠后面；展开状态为
  没有坚持。
- **独立会话**：无路径会话保留在单独的会话中
节并且永远不会继承最后一个活动项目的工作区。
- **并发**：shell 一次选择一个可见项目，同时
  代理运行状态仍然由会话控制。切换项目选项卡不会
  取消背景回合。后台事件仅更新其原始事件
  会话并且永远不会更改活动会话、页面、项目或键盘
  焦点。

### 3. 3 拉取请求
带计数的分段 Open/Draft/All 过滤器；行带有图标板、数字、
标题、状态徽章、分支元、外部链接和“与代理一起审核”
（创建聊天回合）。需要活动工作区和 `gh`。

### 3. 4 预定
创建卡片 + 任务行（cadence/enabled 徽章、提示预览、上次运行、
立即运行/切换/删除）。现在运行会打开一个带有提示的会话。
新任务默认为 Agent。允许保留已迁移的 Plan 或 Goal 任务
已存储，但在提供商、工件之前明确拒绝无人值守的运行，
或使用 `PLAN_REQUIRES_INTERACTIVE_SESSION` 排队工作；它无法显示或
自动批准合同。
用户必须在启用无人值守之前显式将其切换到 Agent
执行。

### 3. 5 任务历史
所有产出过一轮对话的任务，最新的排在前面，按天分组。行内显示标题、最后活动、
消息数与工作空间；右侧详情复述这些事实并补上模型，三个动作平铺：**重跑**
（新建任务并重放首条用户消息）、**只复用输入**（同一段提示词，不绑定工作空间）、
**复用工作空间**（在该目录下开一个空任务）。来自 Pi 的外部转录只读展示。
重跑不改写历史：原来那行仍留在列表里，页面可从侧边栏底部与搜索进入。

### 3. 6 模板

模板给的是结构，不是措辞：文档、表格、幻灯片三类骨架，带具名空位。左侧按类型
分组列出模板，右侧把所选模板的变量铺成普通表单，下方先显示填好的结果再谈发送。
填充就是真实文本的预览——未能解析的占位符原样保留并列入「还需要」，
被调整的内容（超长取值、没有对应变量的占位符）逐条点名，而不是悄悄改掉。

**插入到输入框**只把填好的骨架追加成草稿，不发送、不新建任务，最后一步仍由用户按下。
**一次填多行**接受制表符或逗号分隔的粘贴内容，首行是变量名时按名称对齐，
逐行报告跳过原因与该行缺少的取值；表格形态无法确认列序时直接说明，
不做静默猜测。页面可从侧边栏底部与搜索进入。

### 3. 7 资料库

资料库是一份「随手要用的文件夹」清单，不是副本仓库。左侧列出已加入的文件夹，
右侧显示所选文件夹的路径与加入时间，另有两个动作：复制它的 `@` 引用、移出资料库。
移出只是忘记这条指针——文件夹仍在原处，页面用一句话写清楚这一点，
否则一个可能删过文件的「资料库」没人敢清理。

条目按路径去重，忽略大小写与分隔符写法，同一个文件夹加两次不会变成两行。
空路径被拒绝，清单有固定上限而不是无界增长。

输入框的 `@` 会把这些文件夹排在文件索引之前——它们是被特意选中的，
且在没有打开工作区时依然可引用。已在文件索引里的同一路径只出现一次。

### 3. 8 专家中心

十二份领域说明书，按分类浏览，搜索框只匹配用户看得见的名称。卡片上是一位专家的
字母块、一句话专长、它偏好的模型；点开是详情条，同样的事实加上两个动作——
用这位专家开工，或加入专家团。

选中专家会把它的说明书写进输入框并回到对话。说明书是提示词文本，不是隐藏的会话
设置，发出去之前你能读、能改；卡片上的偏好模型只是标签——一次点击不该把你换到
另一个模型上。

专家团最多四位专家加一段共同的任务说明。交给专家团时写入的是一段提示词：
要求在同一条助手消息里并行发起 `Task`，每位专家一次、各自交给承载该领域的
子代理预设，然后汇总成**一份**交付物——分歧只在会改变结论时保留，重复项合并，
末尾只列仍需人来决定的事。提示词在发送前同样可见。

### 3. 9 提示词库

输入框上方的一块面板，由工具栏打开。列出这个人真正发过的提示词，最新的在最上面；
置顶会把某一条抬到顶部，而列表本身仍按使用时间排。

发出即收录；斜杠命令不收录，因为把 `/model` 当散文再发一遍什么也不会发生。同样的
文字只是空格不同，算同一条，免得列表被近似重复项填满。

每条带使用次数与标签；标签栏做筛选，搜索框按每个词收窄而不是放宽。点一行把它追加
进当前草稿——不会直接发送——行内操作刻意放在点击区之外，置顶键不会被误当成插入。

输入框为空时按 ↑ 倒序回溯同一份历史。回溯到最旧一条就停；一旦对召回的文字做过修改
也立刻停：从一条已被改写的提示词继续往前翻，等于不问自取地把这次修改丢掉。

### 3. 10 会话标签栏

转录区上方 32px 的一条，且只在开了两个以上任务时出现：单个标签占掉一行高度，
只为说一句「你在这里」。

标签取自会话列表，所以已经不存在的会话不会留下一个标签。当前标签用 2px 下划线；
运行中的任务显示脉冲点，并复用侧栏行与转录条那同一个 `3/8` 派生值。

关掉标签只是收起这条捷径，会话本身仍在侧栏。关掉的是当前标签时，由它右边的邻居
接手，没有右边的就用左边——不会留下一个没人接的空窗格。

### 3. 11 `#` 对话引用

输入框里打 `#` 会列出这个工作区的对话；选中后把 `#"标题"` 写进草稿，就是一段普通
文字——可以重新措辞、挪位置、删掉，和手动敲的没有区别。

选中时不发送任何东西。发送时，每个能对上号的引用变成一个简短的引用块：写明对话标题、
消息条数，以及该转录仍留在窗格内存里时其最后一条回答的结尾。块里明确说这是摘录；
引用时现编的摘要，会是用户从未见过的一句断言。

标题已经对不上任何对话的引用，原样留在文字里：`#"typo"` 是一句没写完的想法，不是
「随便挑个最像的」的授权。引用不会指向正在写的这条对话，一份草稿最多引六条。提示词库
记的是清掉标记后的句子，不是 `#"标题"` 这种语法。

### 3. 12 上下文固定

工具栏上的勾选按钮打开这条对话的轮次列表，勾一段就是固定一段；按钮上的数字是已固定
的数量。

固定的内容**不会**粘进输入框。草稿里始终只有正在写的那句话；发送时勾选项才变成引用
块压在最前面：角色、原文，以及一句「当前转录可能已不含这些内容」。压缩之后，这就是
「引用一份已经谈好的结论」和「让模型去回忆它再也看不到的结论」的区别。

底栏数的是字符而不是 token，因为这才是用户真正能控制的量。每条消息最多八段、
1600 字符；放不下的整段丢弃而不截半，消息发出后勾选即清空，免得同一段历史被悄悄
重复发送。

### 3. 13 语音输入

输入框工具栏上的麦克风把话直接听写进草稿的光标处。识别引擎由平台提供：这个版本要么
带语音服务，要么不带；不带时按钮置灰并在提示里说清楚，而不是按下去才失败。

用户能看到的状态是「空闲 / 请求权限 / 正在听 / 被拒绝 / 失败」；正在听时按钮上有脉冲
点，再按一次即停止。只有**最终**识别结果会写进草稿；中间结果只出现在提示里随即丢弃，
否则引擎把「发出去了」修正成「已发出」时，两个版本都会留在框里，用户没法判断模型读的
是哪一个。

听写只写入草稿文本，绝不替用户发送；刚听写完发出的消息，走的是和手打一样的提交路径。

### 3. 14 扩展

扩展目标是专注于插件的页面，使用紧凑标头并且只保留两个选项卡：
**已安装**和**市场**。已安装页按需要注意/可用更新/活动/关闭分组，每组标签
下以柔和色块行堆叠显示插件（D296）；市场页继续使用浏览和安装卡片网格。
整页不画分割线：标头、工具栏、行、来源设置、卡片以及详情抽屉的各节都靠色调
与间距区分，细线只保留给浮层（菜单、抽屉、对话框）。市场来源设置只显示来源选择器，
不再显示重复的提供商说明或当前来源状态行。MCP、技能和子代理不再是扩展页的选项卡或区块。

### 3. 15 设置（全页接管）
设置替换整个外壳（D063）：返回应用程序、搜索和带有简洁平行标签的分组设置导航栏。智能体
分组包含独立的技能、MCP 和子代理页面，并与说明、模型配置并列；选择它们
会切换页面目的地，而不是在一个能力面板内切换选项卡。
外观位于常规；全局人工智能行为（权限和上下文
管理）存在于全局人工智能内部；键盘快捷键和 global/project
指令有其自己的目的地；供应商管理位于内部
模型配置。导入扫描支持本地代理存储和呈现
可折叠组中的候选人。项目路径是备用分组
与默认源分组一起，每次扫描或分组更改都会开始
所有团体都崩溃了。项目档案拥有持久的 D086 项目索引
（搜索、添加、展开、固定、archive/restore、关闭和重新打开）并且始终包括
存档记录。打开或切换项目会保留侧边栏选项卡，选择
该项目作为活动工作区，然后返回聊天。其他保留的选项卡
保持开放。扩展管理仍然完全独立于应用程序外壳扩展目标（见 §3.5）。设置 > 智能体
遵循以下共享能力契约：

- 技能和 MCP 使用单列堆叠的全局/项目卡片区块。每个区块有安静的标题行：作用域
  标题与说明、解析后的 `.agents` 路径、本地化计数和操作；项目区块显示最近项目
  选择器。项目项优先于全局项。
- 每个区块的技能只有一个原生“导入”操作，只接受一个文件，并物理复制到选中的
  `.agents/skills` 目录。
- 每个区块的 MCP 只有一个“新增”操作；新增和编辑复用 `McpEditorSheet` 二级模态框，
  包含 stdio/HTTP 分支、校验、同级别重名拦截、编辑时锁定 ID、作用范围和测试
  连接反馈。
- 子代理使用 `~/.agents/subagents` 下的单个全局宽区块，没有项目选择器、项目区块
  或项目级开关。新建或编辑子智能体时，固定模型从已配置的提供商模型中选择，或沿用
  会话模型，不需要手打 `provider/model` 标识。
- 三个列表随页面自然流动，在面板内显示安静的居中空态；关闭行调暗图标与文案但
  保持开关清晰，加载渲染同构骨架行，启用状态写入应用本地而不是能力文件。
- 隐私说明是系统分组中与信息并列的目的地。它只回答一个问题：点击发送时什么会
  离开本机。答案是一张三列表格（数据 / 会离开 / 只留本机），共六行：你输入的内容、
  工具结果、工作空间文件、API 密钥、用量与错误、应用遥测。行定义来自
  `lib/privacy-manifest`，两栏因此不会各说各话，每个键都会在全部已发布语言中校验。
  页面上没有法律长文：一句说明、一张表，底部入口跳转到日志目录。

## 5. 导航模型

- `page` 状态：`chat | pulls | scheduled | plugins | settings`； `chat` 是
  对话表面路线，而不是操作模式。项目
  archive 是 `projects` 设置选项卡而不是独立页面。
- 目的地历史是线性的； `Cmd/Ctrl+[` 和 `Cmd/Ctrl+]` 遍历它，
  没有持久的 back/forward chrome。插件页激活时，页脚插件按钮复用
  一次后退（见 §2 Shell 区域），不新增独立的前进/后退控件。
- 当项目选项卡的路径与路径不同时，选择项目选项卡会重用 `project.set`
  选择主机工作区并保留其他选项卡。
- 选择项目范围的线程会在切换到之前激活其项目
  `chat`。选择临时线程会清除可见的活动工作区
  在加载之前。
- 新任务打开一个未持久化的草稿：在第一条消息创建当前项目或临时
  范围中的会话之前，不会产生会话或侧边栏历史记录行（D220；修订
  D088/D093 的空草稿堆叠规则）。

## 7. 依赖于状态的 chrome

- 未配置提供商 → 首次运行前阻止设置指导
  （`MODEL_NOT_CONFIGURED`）。
- 无工作区 → 无项目下划线的主页英雄；拉取请求显示
  工作区所需的空状态。输入框从不渲染工作区轨道。
- 后台项目会话 → 原始项目行保留其
  running/error 指标。选定的壳状态可以独立移动，同时
  会话工具根仍然与其持久项目绑定；它的文物是
  保留在该会话的工作面板上下文中，无需打开或激活
  当前所选项目上的选项卡。消息、工具事件、权限
  请求和小组资源仍限于该会议。明确地
  打开对话会恢复其保留的面板上下文并显示任何内容
  待批准的许可卡及其原始截止日期。
- Completed/failed 转不可见→ host-core 附加一个持久的
  收件箱行。结果显示在可见的、集中的当前聊天和每个
  `aborted` 转不追加。后台会话和任何回合结束时
  窗口未聚焦仍在追加。侧边栏页脚铃铛只列出 `task.failed` 行，徽章也只
  统计未读的失败；顺利完成的记录仍持久保存，用于侧边栏结果徽标和原生通知，
  但永不出现在收件箱里（D295）。选择一行标记其已读取并激活其绑定
  project/session。
  仅当
  应用程序窗口未获得焦点，单击它会在激活之前使窗口获得焦点
  同一次会议（D117）。接收持久通知或本机通知
  事件永远不会自行导航；只有显式激活才可以。
- 后端降级→状态胶囊（重新启动）或带有打开的致命横幅
  日志（D080）；输入框提交的内容在关闭时被拒绝并出现可读错误。
  - Plan/Goal 检查点 → 原始会话仅显示结构化标题
  以及其不可变的 `.pi/plan/*.md` 工件的开场白。渲染器保留最新的
  每个会话的 proposal/execution 快照仅适用于当前渲染器
  生命周期，由现场主持人活动更新；只有一个活动的 `pending` 行构成
  审批门。通过 `plans.pending` 重新加载，同时保留相同的主机
  alive 恢复了一个仍然悬而未决的行及其原始截止日期。被拒绝，
  过期、approved/completed 和中断的终端卡不属于
  再水化；终端卡可能保持可见且不可操作，直到
  渲染器重新加载。拒绝、过期或中断清除了批准之门，
  使会话保持合同状态且可编辑，并且需要稍后转向
  创建一个新的工件。在等待期间，草案仍然可见，但
  只读且仅启用“批准”或“拒绝”操作。 Host/app 重启
  在 RPC 之前中断之前的工作，没有重播或过时的操作；待定
  未批准的工作仍保留 Plan，而已批准的工作则中断执行
  仍然是 Agent。 UI 不需要显示中断的终端
  重启后的快照。
