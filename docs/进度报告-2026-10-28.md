### W-05 任务进程步骤 ✅

`第 3/8 步` 常驻转写流之上，当前步高亮，点击跳到那一步的起始工具行。

- **不落库、不加迁移**：步骤列表从 `planCheckpoints[sessionId].markdown`（用户批准的那份快照）解析；当前位置从转写里成功的 `UpdateStep` 工具行重放。因此重启、第二个窗口、侧栏读到的是同一组数字，不需要同步计数器。
- 解析顺序：勾选框 → 编号列表 → `Step N:` → 编号标题，首个产出 ≥2 项的形态胜出（先认勾选框很关键：计划里的「验收标准」也是编号列表，不能被当成步骤）；跳过围栏代码，上限 40。
- 推进靠惰性工具 `UpdateStep`：只在 `autonomousExecution && mode === "agent" && planSteps.length >= 2` 时进工具目录；它不改任何状态，只校验序号。批准执行时把 `<approved-steps>` 清单注入指令，要求「进入第 n 步前调用 `step=<n>`」；普通 prompt 会清空并在重建目录时摘掉这个工具。
- 步骤条挂在 `.thread-scroll` **之外**（不随转写滚动，也不影响 minimap 测高）；阅读窗口 / 历史分页时隐藏，因为那页可能没加载到标记行，显示 `0/8` 是撒谎。
- 模型不调用 `UpdateStep` 时，条显示「共 N 步，待开始」而不是假装有进度。
- 落点：`packages/shared/src/plan-steps.ts`、`packages/agent-runtime/src/runtime.ts`、`apps/desktop/src/components/PlanStepBar.tsx`、`ChatTranscript.tsx`、`styles/chrome.css`
- **方案偏差**：方案要求改 Rust `plans/{model,repository}.rs`，实际零改动——快照与工具行本就持久化，重放即一致。
- 验证：`packages/shared/src/plan-steps.test.ts`（15）、`packages/agent-runtime/src/runtime.test.ts`、`test/plan-steps-contract.test.mjs`（6）

首事件前的等待分三档：**20s / 45s / 120s**，档位只升不降，因此每一档在 `aria-live="polite"` 区域里只播报一次；第三档把提示提到 `--ds-text-secondary`，因为它要说的不是「稍慢」而是「多半卡住了」。

- 阈值与文案 key 收在一个纯函数里：`silence-ladder.ts`（`SILENCE_RUNGS` / `silenceLevel` / `SILENCE_HINT_KEYS`），组件只把 level 翻成文案，改阈值不用碰文案、加语言不用碰组件。

- 验证：`test/slow-response-hint.test.mjs`（3 例，含 8 个语言的 key 完整性）

## 6. 已知债务与口径偏差

1. **W-08 的看门狗在 renderer 内**，没有 `electron/main/runtime/watchdog.ts`。三档语义等价（单调升档 → 每档只播一次），但「应用在后台时是否也计时」取决于窗口是否被节流，未做专门验证。

4. **W-03 落点在顶栏**而非 `transcript/`，§11 已注明。
5. **W-34 未按方案重做**：既有 MCP 市场已覆盖大部分需求，建议先做一次体验走查再决定是否补工。
