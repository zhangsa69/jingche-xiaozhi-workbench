## 1. 引言

### 1.1 编写目的

本文档定义京车小智工作台（以下简称「本产品」）在开发启动前的完整技术基线，作用有三：

1. **共识基线**：统一产品、开发、测试、运维对系统边界、职责划分与技术选型的认知，避免开发期反复推翻架构。
2. **实现依据**：为每个模块提供可落地的设计约束、数据结构与接口契约，使实现方无需二次设计即可开工。
3. **验收依据**：所有需求均可判定，附录 F 建立「需求 → 设计章节 → 验收项」的追踪关系。

### 1.2 文档范围

本文覆盖首个可交付版本（V1）及已规划阶段二能力的设计基线，包括：需求规格、总体设计、技术选型论证、详细设计、数据设计、接口设计、安全设计、关键流程、开发计划、测试验收、发布规划、风险。

### 1.3 不适用范围

以下内容不在本文定义范围内，由各自独立文档承接：

- 产品宣传口径、定价与商业化方案
- 具体代码实现细节与逐行注释级说明
- 单个 Bug 的修复方案
- 上游开源依赖的内部实现原理

## 2. 项目概述

### 2.1 背景与问题陈述

现有 AI 编程 Agent 主要存在三类形态缺陷：

1. **终端形态**：交互密度低，难以承载长会话、多文件变更审阅与多任务并行。
2. **IDE 内嵌形态**：Agent 生命周期与单一编辑器绑定，用户被迫更换工具链。
3. **云端绑定形态**：会话与代码上下文需经厂商中转，模型不可替换，数据主权不在用户。

同时，团队日常的另一类高频知识工作——**会议记录与纪要整理**——仍依赖人工听录音、手工整理，缺乏与开发工作台打通的自动化路径。

### 2.2 产品目标与价值主张

构建一个**本地优先的 AI 智能体桌面工作台**，达成四点：

1. **模型自由**：不锁定任何模型厂商，用户可接入任意协议兼容的服务或本地模型。
2. **数据本地**：项目、会话、音频、纪要保存在用户设备，凭证存于系统密钥库，无强制云端中转、无遥测上报。
3. **能力可扩展**：核心保持克制，能力通过插件、Skills、MCP、Subagent 扩展，而非不断内置功能。
4. **长期任务可用**：面向半小时至数小时的长任务设计，具备断点、恢复、委派与并行能力。

### 2.3 目标用户与核心场景

| 用户类型 | 核心场景 |
|---|---|
| 个人开发者 | 在本机项目中让 Agent 读写代码、执行命令、审阅变更 |
| 小团队/技术负责人 | 多人并行任务委派、方案先审批再执行、跨会话恢复长任务 |
| 技术管理者/项目经理 | 会议现场录音，自动生成结构化会议纪要并导出 Word 分发 |
| 插件/扩展作者 | 基于插件契约扩展工具、面板、主题与常驻服务 |

### 2.4 成功标准

| 维度 | 判定标准 |
|---|---|
| 可用性 | 新用户从安装到完成首轮 Agent 任务 ≤ 5 分钟 |
| 稳定性 | 单会话连续 2 小时以上运行不崩溃，重启后可恢复现场 |
| 安全 | 所有高权限操作均经权限判定，无绕过路径 |
| 扩展性 | 新增一种工具/面板/主题无需修改核心代码 |
| 会议能力 | 1 小时会议从结束到导出 Word 纪要 ≤ 3 分钟（不含人工编辑） |

### 2.5 项目范围

**V1 必须包含**：桌面外壳、项目与会话管理、三种工作模式、多 Provider 模型接入、Agent 工具与权限体系、变更审阅、Subagent 委派、插件体系、Skills、MCP、历史会话导入、通知与更新、跨平台打包、**会议纪要生成**。

**V1 明确不做**：账号体系与云端同步、强制中转网关、多人实时协同编辑、移动端、系统音频采集、云端语音转写、会议视频处理。

### 2.6 约束与假设

| 类型 | 内容 |
|---|---|
| 技术约束 | 桌面容器限定 Electron 系；特权层须为可静态编译的原生语言；必须支持三平台 |
| 数据约束 | 不允许依赖云端数据库；凭证不得落盘明文 |
| 合规约束 | 录音功能须提供知情提示，录音与声纹默认仅本地存储 |
| 资源约束 | ASR 与说话人分离须在消费级设备（8 核 CPU / 16GB 内存）可用 |
| 外部假设 | 上游 Agent 引擎（`pi-ai` / `pi-agent-core`）保持稳定 API；模型服务商兼容 OpenAI 风格接口者占多数 |

## 4. 总体设计

### 4.1 设计目标与原则

| 原则 | 含义 | 落地约束 |
|---|---|---|
| P1 UI 与特权运行时分离 | 界面层不持有任何系统级能力 | 渲染层禁用 Node 集成，仅经预加载桥暴露白名单能力 |
| P2 特权能力集中归属 | 文件系统、持久化、权限判定由单一组件独占 | 数据库与文件写入只能由宿主层执行 |
| P3 Agent 语义归属清晰 | 模型交互与工具循环由 Agent 运行时负责 | 编排层不得实现 Agent 循环 |
| P4 跨边界契约强类型 | 所有跨进程结构由共享层统一定义并校验 | 禁止 `any` 穿透边界 |
| P5 核心克制、能力外置 | 新功能优先以扩展形式提供 | 核心新增须说明为何不能做成插件 |
| P6 长任务优先 | 一切状态变更可恢复 | 关键状态须落盘，重启可重组 |
| P7 默认安全 | 未声明即禁止 | 权限、网络、文件访问均默认拒绝 |

### 4.2 架构风格与进程模型

采用**分层 + 多进程**架构，四个进程边界：

```text
┌───────────────────────────────────────────────────────────────┐
│ 渲染进程（React UI，非特权）                                   │
│ 会话/项目/审阅/设置/插件/会议纪要面板                          │
│ 无 Node 集成 · 无直接文件与数据库访问                          │
└──────────────────────────▲────────────────────────────────────┘
                           │ 预加载桥（白名单 IPC）
┌──────────────────────────┴────────────────────────────────────┐
│ 编排进程（Electron 主进程，瘦编排）                            │
│ 窗口与生命周期 · IPC 路由 · 进程监督 · 更新 · 托盘             │
│ 录音状态机 · 音频管线编排 · 导出任务调度                       │
└───────▲────────────────────────────────────▲─────────────────┘
        │ 本地 RPC（stdio JSON-RPC/NDJSON）    │ 进程桥（stdio）
┌───────┴──────────────────┐      ┌───────────┴─────────────────┐
│ 特权宿主（Rust）         │◄────►│ Agent 运行时（Node）        │
│ 工具执行 · 权限判定      │      │ 模型调用 · 轮次循环 · 流式  │
│ 持久化 · 密钥 · 审计     │      │ 上下文管理 · 委派           │
│ 音频/转写存储 · docx     │      └───────────┬─────────────────┘
└───────▲──────────────────┘                  │ HTTPS
        │ stdio                                ▼
┌───────┴──────────────────┐          ┌──────────────────────┐
│ 语音处理进程（Rust）     │          │ 模型服务（用户自配） │
│ ASR · 声纹 · 说话人聚类  │          └──────────────────────┘
└──────────────────────────┘
```

设计要点：

1. **语音处理独立成进程**：ASR 与声纹推理为 CPU 密集型，独立进程可避免阻塞编排与 UI 主链路，并允许单机降级（低配设备仅关闭实时字幕，保留会后整段转写）。
2. **音频数据不经过渲染层落盘**：渲染层只负责采集与波形展示，音频分片经预加载桥转交编排层，再由宿主层写入磁盘。
3. **文档生成在宿主层**：`.docx` 由 Rust 生成，复用工作区路径校验与文件写入通道，不新增第二条写盘路径。

### 4.3 模块划分与职责矩阵

| 模块 | 所在层 | 职责 | 明确不负责 |
|---|---|---|---|
| 桌面外壳 | 编排层 | 窗口、菜单、托盘、生命周期、单实例 | 业务逻辑 |
| 预加载桥 | 边界 | 白名单能力暴露、参数快照 | 业务校验 |
| IPC 路由 | 编排层 | 通道注册、转发、错误归一 | 权限判定 |
| 进程监督 | 编排层 | 子进程拉起、健康检查、重启、退出清理 | 业务状态 |
| Agent 运行时 | 执行层 | 轮次循环、模型调用、流式归一、工具请求、上下文压缩、委派 | 文件与数据库直写 |
| 会话状态机 | 执行层 | 轮次/审批/队列状态、事件发布 | 模型细节 |
| 特权宿主 | 特权层 | 工作区约束、工具执行、权限判定、持久化、密钥、审计 | 模型调用 |
| 插件宿主 | 特权层 | 清单校验、权限授予、生命周期、运行隔离 | 插件业务 |
| 语音处理 | 独立进程 | 音频转写、声纹提取、说话人聚类 | 持久化 |
| 会议纪要 | 跨层 | 录制编排、转写装配、模板编译、纪要生成、文档导出 | 模型接入实现 |
| 共享契约 | 公共 | 类型、schema、常量、错误码 | 任何运行时依赖 |

### 4.6 演进与扩展设计

1. **新增工具**：优先以插件贡献，核心仅在需要特权能力时内置。
2. **新增面板**：插件声明视图贡献点，由外壳动态挂载，不改动导航核心代码。
3. **新增协议**：接口按版本化设计，主版本不兼容变更须走 ADR 并保留过渡期。
4. **新增领域模块**（如本次会议纪要）：遵循「渲染层展示 → 编排层调度 → 宿主层持久化」的固定切分，禁止跨层直连。

## 5. 技术选型论证

### 5.1 桌面容器

| 方案 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| Electron | 生态成熟、跨平台一致、Node 侧 Agent 生态可直接复用、调试链路完整 | 包体大、内存占用高于原生 | **采用** |
| Tauri | 包体小、内存低 | WebView 行为跨平台差异大、需自建大量桌面能力、Agent 生态适配成本高 | 备选 |
| 原生（Qt/Flutter） | 性能最优 | 三平台 UI 一致性成本与开发周期不可接受 | 否决 |

判定依据：本项目核心复杂度在 Agent 执行与多进程协作，而非 UI 性能；选用 Electron 可将预算集中在差异化能力上。

### 5.2 特权宿主语言

| 方案 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| Rust | 内存安全、单一静态二进制、跨平台交叉编译成熟、SQLite 与加密库生态完善、适合 CPU 密集推理 | 开发效率低于脚本语言 | **采用** |
| Node/TypeScript | 与前端同构、开发快 | 无法提供强隔离，权限边界与渲染层同语言易被穿透 | 否决 |
| Go | 交叉编译简单 | 生态在桌面加密与音视频推理绑定上弱于 Rust | 否决 |

### 5.3 Agent 引擎

| 方案 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| 复用上游 Agent 框架 | 模型适配、流式、工具循环语义现成；上游持续演进 | 受上游 API 稳定性影响，需锁定版本 | **采用** |
| 全自研 | 完全可控 | 模型适配面极广，自研成本与长期维护不可承受 | 否决 |

约束：锁定上游版本，升级须单独评估并回归核心流程。

### 5.4 跨进程协议

| 方案 | 优势 | 劣势 | 结论 |
|---|---|---|---|
| stdio JSON-RPC / NDJSON | 无端口占用、天然进程绑定、易审计、无网络暴露面 | 仅限本机父子进程 | **采用** |
| 本地 HTTP | 调试方便 | 需管理端口与鉴权，存在被本机其他进程访问风险 | 仅用于可选控制面 |
| 共享内存 | 吞吐高 | 复杂度高，收益在本场景不明显 | 否决 |

### 5.5 存储方案

| 方案 | 结论 |
|---|---|
| 会话正文用追加式日志文件，索引与结构化数据用 SQLite | **采用**：日志便于流式追加与崩溃容忍，SQLite 便于检索与事务 |
| 全部塞入 SQLite | 否决：长文本流式写入放大写竞争 |
| 全部用文件 | 否决：检索与关联查询代价过高 |

### 5.6 前端技术栈

React + TypeScript + Vite 系构建 + 原子化 CSS + 轻量状态库 + 类型 schema 校验。理由：类型安全、构建速度快、生态与插件面板动态加载兼容性好。状态管理遵循「状态入 store、流程入 service、纯变换入 reducer」，禁止把复杂流程堆进单一全局 store。

### 5.7 会议纪要模块专项选型

#### 5.7.1 语音识别引擎

| 方案 | 离线 | 中文效果 | 集成成本 | 结论 |
|---|---|---|---|---|
| whisper.cpp 系（GGML 量化模型） | 是 | 好（中等以上模型） | 低（Rust 有成熟绑定） | **采用** |
| sherpa-onnx（含流式模型） | 是 | 中上，流式优势明显 | 中 | 备选，用于低延迟场景 |
| 云端 ASR | 否 | 最好 | 低 | 否决（违反纯本地决策） |

决策要求：

1. 模型不随安装包分发主体，首次进入会议模块时引导下载，校验哈希后存入用户数据目录。
2. 提供至少两档模型：**均衡档**（中等参数量、量化，默认）与**高精度档**（较大参数量，可选下载）。
3. 运行时优先 CPU 多线程；检测到可用 GPU 时可选用硬件加速，但必须保证纯 CPU 路径可用。
4. 中文场景启用前置提示词引导与标点恢复，输出需做数字、日期、单位规范化。

#### 5.7.2 说话人识别

| 方案 | 说明 | 结论 |
|---|---|---|
| 声纹特征提取 + 聚类 | 段级提取特征向量，会议内聚类得到说话人 | **采用（基线）** |
| 端到端分离模型（如神经分离网络） | 精度更高、资源占用大 | 暂不采用 |
| 云端分离服务 | 违反本地化决策 | 否决 |

特征模型选用中文场景表现稳定的说话人确认模型（如 CAM++ 类结构），以 ONNX 形式在语音处理进程中推理。

#### 5.7.3 文档生成

| 方案 | 说明 | 结论 |
|---|---|---|
| Rust 侧生成 docx | 与权限、落盘、审计同层，无新增写盘路径 | **采用** |
| 编排层（Node）生成 | 库生态更丰富 | 否决：形成第二条写盘通道，破坏 P2 |
| 调用外部 Office 进程 | 依赖用户环境 | 否决 |

#### 5.7.4 音频格式

| 方案 | 体积（1 小时） | 说明 | 结论 |
|---|---|---|---|
| WAV / PCM 16kHz 单声道 | ≈ 115MB | 无编码损耗、实现简单、崩溃容错好 | **采用（默认）** |
| Opus | ≈ 15–20MB | 体积优势明显，需编码依赖 | P2 可选压缩 |

默认使用 WAV 分片（每片 5 分钟），会后可选转码压缩。

## 6. 详细设计（核心模块）

### 6.1 桌面外壳

| 能力 | 设计要求 |
|---|---|
| 窗口 | 单主窗口多标签；标签使用惰性挂载，非活动标签保留状态但暂停高频渲染 |
| 生命周期 | 启动顺序固定：外壳初始化 → 宿主进程拉起并握手 → Agent 运行时拉起 → 恢复上次会话 → 渲染首屏 |
| 单实例 | 二次启动仅唤起已存在窗口，并将待打开参数转交首实例 |
| 退出 | 收到退出指令后先执行有序关闭：停止录音 → 结束运行中轮次 → 关闭插件服务 → 关闭宿主进程 |
| 托盘 | 关闭窗口默认最小化到托盘；托盘菜单提供显示窗口、退出、当前任务状态 |
| 菜单 | 菜单项由命令注册表生成，保证快捷键、命令面板、菜单三处一致 |
| 界面缩放 | 支持系统级缩放与用户自选缩放比例，缩放值持久化 |

**顺序与清理约束**：任一子进程启动失败时，外壳须回滚已启动的部分，不得进入半可用状态；关闭流程中每个清理步骤必须有超时，超时后强制结束并记录日志。

### 6.2 UI 与信息架构

#### 6.2.1 导航结构

一级目标页：会话、项目、审阅、插件、**会议纪要**、设置。二级以面板形式在同页展开，避免多层跳转。

#### 6.2.2 交互规范

1. 所有破坏性操作须二次确认，并提供撤销入口（会话删除除外，需输入确认）。
2. 所有异步操作须有明确状态：进行中、成功、失败（含原因与重试）。
3. Agent 运行中，输入区不得锁定，允许排队。
4. 错误提示须包含：发生了什么、可能原因、可执行动作。

#### 6.2.3 设计令牌与主题

颜色、间距、圆角、阴影、字体、动效时长全部以令牌定义，界面代码不得出现硬编码色值。主题通过替换令牌值实现，插件主题亦只允许覆盖令牌。

#### 6.2.4 长列表与流式渲染

1. 消息列表采用窗口化渲染，仅渲染可视区与缓冲区。
2. 流式增量按帧合并写入，避免每条增量触发一次布局。
3. 代码块、表格、图表采用延迟渲染：进入可视区后再解析。

### 6.3 Agent 运行时

#### 6.3.1 轮次引擎

```text
收到 Prompt
  → 组装上下文（系统提示 + 项目说明 + 会话历史 + 压缩摘要 + 附件）
  → 调用模型（流式）
  → 归一化事件（文本增量 / 思考增量 / 工具请求 / 用量 / 结束原因）
  → 若有工具请求：转交宿主执行 → 结果回填 → 继续下一轮
  → 达到停止条件：结束并持久化
```

停止条件：模型自然结束、轮次内工具调用预算耗尽、用户中止、权限被拒且无替代路径、致命错误。

#### 6.3.2 上下文管理

| 机制 | 设计要求 |
|---|---|
| 窗口预算 | 按模型配置的上下文窗口计算可用预算，预留输出空间 |
| 压缩 | 达到阈值时对早期轮次做摘要压缩，保留决策与结论，丢弃冗余过程 |
| 项目说明 | 自动加载项目内约定文件作为长期指令，注入优先级高于会话历史 |
| 附件 | 文件引用按需读取，超限内容截断并标注 |
| 检查点 | 每轮结束与关键状态变更处写入检查点，供恢复 |

#### 6.3.3 错误与重试

1. 可重试错误（限流、网关抖动、超时）按指数退避重试，次数与上限可配置。
2. 不可重试错误（鉴权失败、模型不存在、上下文超限）直接失败并给出可执行指引。
3. 流中断时保留已产出内容，标记该轮不完整，允许续跑。
4. 推理类模型的思考内容须在重试与续跑时保持一致传递，不得丢失。

#### 6.3.4 委派

主 Agent 通过工具调用派生子 Agent；子 Agent 拥有独立上下文与独立事件流，主 Agent 仅接收结构化结果摘要。取消、超时、父会话切换必须级联下游。

### 6.4 特权宿主

#### 6.4.1 职责切分

| 子域 | 职责 |
|---|---|
| 工作区 | 项目根登记、路径解析与越界拦截、相对路径规范化 |
| 工具执行 | 读、写、删、列目录、执行命令、搜索；统一超时与输出截断 |
| 权限 | 策略求值、模式匹配、审批请求生命周期、超时拒绝 |
| 持久化 | 会话、消息、轮次、审批、插件、模板、会议、转写、声纹、导出记录 |
| 密钥 | 系统密钥库读写，禁止明文落盘 |
| 审计 | 高权限操作留痕，可导出 |
| 制品 | 方案文件、音频分片、导出文档的落盘与校验 |

#### 6.4.2 路径安全

所有文件操作以「会话绑定的项目根」为基准，执行前做四步校验：

1. 规范化（处理 `..`、符号链接、大小写差异）。
2. 判定是否位于项目根之内（含新文件父目录）。
3. 拦截敏感路径（系统目录、密钥目录、应用数据目录）。
4. 记录审计条目后再执行。

#### 6.4.3 权限模型

权限判定顺序：**模式策略 → 工具类别 → 路径/命令风险等级 → 用户确认**。

| 要素 | 设计 |
|---|---|
| 判定输入 | 会话、工具名、参数、目标路径、当前模式、权限模式 |
| 结果 | 允许 / 拒绝 / 需确认 |
| 超时 | 需确认未响应时默认拒绝并明确告知 Agent |
| 记忆 | 支持「本次会话内允许同类操作」，不得跨会话记忆 |
| 不可绕过 | 渲染层提交的请求参数不参与策略求值的可信输入 |

### 6.5 插件系统

#### 6.5.1 清单模型

清单须包含：标识（小写点分命名）、名称、版本、清单版本号、兼容的主版本范围、贡献点声明、权限声明、入口。

#### 6.5.2 贡献点

| 贡献点 | 说明 | 权限要求 |
|---|---|---|
| 工具 | 向 Agent 注册工具 | `tools` |
| 命令 | 注册可从命令面板/输入框调用的命令 | `commands` |
| 技能 | 提供可复用提示词与流程 | `skills` |
| 面板/视图 | 挂载到工作区或会话界面 | `views` |
| 主题 | 覆盖设计令牌 | `themes` |
| 常驻服务 | 后台长生命周期服务 | `services` |
| 外部工具服务 | 注册 MCP 服务配置 | `mcp` |
| 子智能体定义 | 注册预置子智能体 | `subagents` |

#### 6.5.3 生命周期与隔离

```text
发现 → 校验清单 → 展示权限 → 用户授权 → 加载 → 注册贡献点
     → 运行（沙箱进程内，受限能力集）
禁用 → 注销贡献点 → 清理定时器/监听/连接 → 结束进程
卸载 → 禁用流程 + 删除文件 + 清除授权记录
```

隔离要求：

1. 插件运行在独立进程，崩溃不得影响主进程与宿主。
2. 插件能力通过受控桥提供，禁止直接访问数据库、密钥、任意文件。
3. 插件越权调用须被拒绝并记录审计。
4. 文档须明确：插件属于用户主动信任代码，非操作系统级沙箱。

### 6.6 扩展面

| 扩展面 | 设计要求 |
|---|---|
| Skills | 目录 + 说明文件 + 可引用资源；支持全局与项目级；注入时按任务相关性选取 |
| MCP 客户端 | 支持本地命令与远程端点两类传输；连接失败须退避重连；工具命名加服务前缀防冲突 |
| CLI 扩展兼容 | 加载既有扩展文件，映射到工具/命令/钩子注册；依赖安装须限定为注册表来源且禁止执行安装脚本 |
| 本地控制面 | 默认关闭；仅绑定回环地址；启动时生成一次性凭证；调用与界面共用同一套处理逻辑与权限判定，不另建旁路 |

### 6.7 更新与分发

1. 更新源固定为项目发布地址，渲染层不得提供地址。
2. 更新流程：检查 → 展示版本说明 → 下载 → 校验 → 安装 → 重启生效。
3. 平台差异：支持应用内安装的平台完成闭环；不支持者跳转下载页并明确说明。
4. 更新失败不阻塞应用使用，且保留回滚到上一版本的能力。
5. 更新内容不经过宿主层与 Agent 层，避免权限放大。

## 7. 详细设计（会议纪要模块）

### 7.1 模块定位与边界

| 维度 | 定义 |
|---|---|
| 定位 | 独立功能域，与三种工作模式平级，不参与 Agent 循环 |
| 复用 | 模型配置与 Provider 绑定、权限体系、审计、保存约束、通知 |
| 不复用 | 不创建第二套会话存储、不绕过宿主写盘、不新增鉴权体系 |
| 依赖 | 麦克风权限、本地 ASR 与声纹模型、可用模型服务（总结阶段） |
| 边界 | 不处理视频、不做系统音频、不做云端转写、不做多人实时协作编辑 |

### 7.2 分层职责

| 层 | 职责 | 禁止事项 |
|---|---|---|
| 渲染层 | 录制面板、波形与计时、实时字幕、说话人校正、模板选择、纪要编辑与预览 | 直接写文件、直接调用 ASR 进程 |
| 编排层 | 录音状态机、音频源与设备管理、分片调度、任务编排、导出触发、进度事件 | 实现转写算法、直接写数据库 |
| 特权宿主 | 音频与转写持久化、模板与纪要存储、声纹档案、docx 生成与落盘、权限与审计 | 模型推理 |
| Agent 运行时 | 纪要总结的模型调用（一次性完成任务，非会话模式） | 持有音频数据 |
| 语音处理进程 | VAD、ASR 推理、声纹特征提取、说话人聚类 | 持久化、网络访问 |

### 7.3 音频采集管线

#### 7.3.1 采集参数

| 参数 | 取值 | 说明 |
|---|---|---|
| 源 | 麦克风（单路） | 不采集系统音频 |
| 采样率（采集） | 48kHz | 设备原生，避免重采样失真 |
| 采样率（处理） | 16kHz 单声道 16bit | ASR 标准输入 |
| 帧长 | 20ms | 供电平计算与 VAD |
| 预处理 | 回声消除开、噪声抑制开、自动增益开 | 由采集端提供，可按设备关闭 |
| 分片时长 | 5 分钟 | 崩溃容忍粒度 |
| 停顿阈值 | 静音 ≥ 600ms 视为语音段结束 | 触发增量转写 |

#### 7.3.2 数据流

```text
麦克风
 → 渲染层采集（Web Audio）
 → 重采样为 16kHz 单声道 PCM
 → 分帧（20ms）计算电平，驱动波形显示
 → 环形缓冲累积
 → 静音检测切出语音段（或达分片时长强制切出）
 → 经预加载桥转交编排层（二进制传输通道）
 → 宿主层追加写入分片文件
 → 同时投递至语音处理进程做增量转写
```

设计要求：

1. 音频数据使用二进制通道传输，禁止 Base64 编码进 JSON。
2. 写盘与转写为并行两条链路，任一链路故障不得中断录制。
3. 录音状态机：`空闲 → 准备中 → 录制中 ⇄ 已暂停 → 收尾中 → 已结束 → 处理中 → 待编辑 → 已定稿`。
4. 收尾阶段必须 flush 未满分片的缓冲，并写入清单文件（分片序号、起止时间、字节数、校验和）。
5. 每 30 秒更新一次录音心跳记录，用于崩溃后恢复判定。

### 7.4 语音转写设计

#### 7.4.1 引擎抽象

```text
interface AsrEngine {
  transcribe(request: AsrRequest): AsrResult
}
AsrRequest: 音频分片、采样率、语言提示、前置提示词、是否返回词级时间戳
AsrResult:  文本段数组（起止时间、文本、置信度）、处理耗时、模型标识
```

实现要求：

1. 引擎可替换，默认实现为本地 whisper 系推理，禁止实现中出现远程调用。
2. 模型文件按「标识 + 版本 + 量化档位 + 哈希」登记，加载前校验哈希。
3. 模型缺失时提供下载引导，下载失败可重试，不得静默降级为云端。
4. 推理并发度受 CPU 核数限制，默认保留 1 核给 UI 与主链路。

#### 7.4.2 流式与整段两阶段

| 阶段 | 目的 | 策略 |
|---|---|---|
| 增量转写（录制中） | 实时字幕、可视化 | 短段推理，低延迟优先，允许精度折损 |
| 整段复算（录制后） | 提升准确率 | 按语音段批量推理，含上下文拼接，结果替换增量结果 |

增量与整段结果须以「语音段标识」对齐；复算只替换文本与置信度，不改变说话人归属。

#### 7.4.3 文本后处理

1. 标点恢复与断句。
2. 数字、日期、金额、单位规范化。
3. 常见口头语与重复词清理（可通过模板开关控制）。
4. 专业术语词表：用户可为项目维护术语表，作为前置提示参与解码。

### 7.5 说话人识别设计

#### 7.5.1 基线流程（自动聚类 + 人工校正）

```text
语音段 → 声纹特征提取 → 会议内相似度矩阵
      → 聚类（按阈值自适应确定人数上限）
      → 生成说话人 S1..Sn
      → 时间段归属：按与该段重叠最大的说话人区间赋值
      → 短段（< 1s）采用时间邻近传播
      → 用户改名 / 合并 / 拆分 → 全量文本同步
```

约束：

1. 聚类人数上限可配置（默认 8），超出时提示用户手动拆分。
2. 每个说话人须展示累计时长与发言占比，辅助用户判断。
3. 人工校正结果作为该会议的最高优先级归属，重新转写不得覆盖。

#### 7.5.2 声纹库自动认人（增强能力）

| 环节 | 设计要求 |
|---|---|
| 注册 | 录制 15–30 秒引导语，或从既有会议指定说话人；生成档案向量并保存 |
| 匹配 | 会议聚类结果与档案库做相似度比对，超过阈值判定为同一人 |
| 置信度 | 区分高置信（自动采用）与低置信（建议、需确认）两档 |
| 纠正 | 用户改判后，可反向更新档案（提示后执行） |
| 隐私 | 声纹默认关闭；档案仅本地存储；删除须物理清除且不可恢复 |
| 生命周期 | 档案与人员名绑定，支持重命名、导出禁用、批量清除 |

### 7.6 模板引擎

#### 7.6.1 模板结构

模板由「元信息 + 章节 + 字段 + 提示约束」组成：

```
模板 = {
  标识, 名称, 适用场景,
  章节列表: [ { 标题, 说明, 字段列表: [ { 名称, 类型, 必填, 说明 } ] } ],
  全局约束: 语气、详细度、是否需要待办提取、是否输出分歧点,
  导出样式: 样式标识
}
```

#### 7.6.2 内置模板

| 模板 | 章节构成 |
|---|---|
| 决策型 | 会议信息 → 背景 → 议题与讨论 → 结论与决议 → 待办事项 → 风险与遗留问题 |
| 周会型 | 会议信息 → 本周进展 → 问题与阻塞 → 下周计划 → 待办事项 |
| 访谈型 | 会议信息 → 受访者背景 → 核心观点 → 引用要点 → 结论与后续 |

#### 7.6.3 自定义与校验

1. 用户可复制内置模板后修改章节与字段。
2. 保存前校验：必填字段存在、章节标题非空、字段类型合法、总章节数有上限。
3. 模板变更不影响已生成纪要；纪要记录其使用的模板版本。

### 7.7 纪要生成设计

#### 7.7.1 生成链路

```text
转写文本 + 说话人映射 + 模板
 → 预处理：按时间切块（默认 8–12 分钟/块），块内保留说话人标签
 → 分块归纳（map）：每块输出要点、结论候选、待办候选、未决问题
 → 汇总（reduce）：合并去重、按时间排序、与模板章节对齐
 → 结构化约束输出（JSON）：按模板字段填写
 → 校验：必填项完整性、待办是否含责任人/期限、是否存在无来源断言
 → 渲染为可编辑纪要 → 用户编辑/重生成 → 定稿
```

#### 7.7.2 生成约束

1. **不得编造**：信息不足时输出「未提及」，禁止推测人名、数字与结论。
2. **可溯源**：结论与待办须可关联到转写中的时间区间，界面支持点击跳转原文。
3. **说话人一致**：输出使用用户确认后的显示名，不使用 S1/S2 默认标签。
4. **长度控制**：纪要长度与会议时长挂钩（默认约每 10 分钟 150–250 字），避免全量复述。
5. **模型无关**：使用当前会话选定的模型；模型不可用时降级为「纯转写纪要」（保留分段与说话人，分类由规则完成）。

#### 7.7.3 长会议处理

超过单次上下文预算的会议采用两级归纳：块级摘要与全局摘要均落盘缓存，支持中断续算，避免重复消耗。

#### 7.7.4 编辑与版本

| 能力 | 要求 |
|---|---|
| 局部重写 | 选中段落 → 指令（更简洁 / 更正式 / 补充细节）→ 生成候选 → 替换或保留 |
| 重新生成 | 保留原版本，生成新版本，可对比后采用 |
| 版本 | 每次定稿生成版本号；版本可回滚 |
| 编辑留痕 | 记录编辑时间与操作类型，不记录逐字 diff（体积考虑） |

### 7.8 Word 导出设计

#### 7.8.1 文档结构映射

| 纪要结构 | docx 元素 |
|---|---|
| 会议主题 | 标题（一级） |
| 会议信息表 | 两列表格（字段/值），灰色底纹 |
| 章节标题 | 标题（二级） |
| 正文段落 | 正文样式，首行缩进 2 字符 |
| 讨论要点 | 项目符号列表（最多两级） |
| 待办事项 | 四列表格（事项/责任人/期限/状态） |
| 原始转写附录 | 分页后标题（二级）+ 时间戳段落（灰色小字）+ 正文 |

#### 7.8.2 排版要求

1. 中文字体显式设置东亚字体属性，避免不同办公软件回退为默认字体。
2. 页面 A4，页边距对称；正文行距 1.5 倍。
3. 页眉包含会议主题与日期，页脚包含页码（第 X 页 / 共 Y 页）。
4. 必填元信息缺失时保留占位符（如「未填写」），不得留空行。

#### 7.8.3 落盘与命名

| 项 | 规则 |
|---|---|
| 默认目录 | 项目根下「会议纪要」目录；无项目时使用用户数据目录下的导出目录 |
| 路径校验 | 复用宿主路径安全四步校验，越界拒绝 |
| 命名 | `YYYY-MM-DD_会议主题_会议纪要.docx`，主题去除非法字符并截断至 60 字符 |
| 冲突 | 同名追加序号 `_2`、`_3` |
| 事务 | 先写临时文件，校验可打开后再原子重命名，失败不留半成品 |
| 记录 | 导出成功后写入导出记录（路径、大小、模板、时间） |

### 7.9 状态机与恢复

| 状态 | 允许转入 | 说明 |
|---|---|---|
| 空闲 | 准备中 | — |
| 准备中 | 录制中 / 失败 | 设备与权限检查 |
| 录制中 | 已暂停 / 收尾中 / 异常 | 异常时保留已落盘数据 |
| 已暂停 | 录制中 / 收尾中 | 暂停不写音频 |
| 收尾中 | 处理中 | flush 缓冲、写清单 |
| 处理中 | 待编辑 / 失败 | 整段转写 + 说话人分离 + 可选总结 |
| 待编辑 | 已定稿 | — |
| 已定稿 | 已导出 / 待编辑 | 编辑后重回待编辑 |
| 异常 | 处理中 / 待编辑 | 依据清单判定可恢复范围 |

恢复规则：重启后扫描存在但未结束的会议，若清单文件完整则进入「处理中」，否则标记为「部分音频」并允许用户选择「仅处理已有分片」。

## 8. 数据设计

### 8.1 数据分类与归属

| 数据类别 | 归属层 | 存储介质 | 是否可含隐私 |
|---|---|---|---|
| 项目登记、会话元信息、轮次、审批、插件、模板 | 宿主层 | 索引库 | 否 |
| 会话消息正文 | 宿主层 | 追加式日志文件 | 是（含代码与对话） |
| 方案制品、导出文档 | 宿主层 | 项目工作区文件 | 是 |
| 会议音频、转写、声纹、纪要 | 宿主层 | 工作区或用户数据目录 | 是（敏感） |
| 用户设置 | 宿主层 | 配置文件 | 否 |
| 凭证、密钥 | 宿主层 | 系统密钥库 | 是（最高敏感） |
| 界面临时状态 | 渲染层 | 内存 | 否 |
| 运行日志 | 编排层 | 日志文件 | 可能含路径，不含凭证 |

**硬约束**：索引库只能由宿主层打开；任何其他进程只能通过 RPC 访问。

### 8.2 概念模型

```text
项目 1 ── n 会话 1 ── n 轮次 1 ── n 消息
                 │
                 ├── n 工具调用记录
                 ├── n 审批记录（含方案审批）
                 └── 0..1 会议记录（会议可独立于会话存在）

会议 1 ── n 音频分片
     1 ── n 转写段 n ── 1 说话人
     1 ── n 说话人（S1..Sn）n ── 0..1 声纹档案
     1 ── 1 纪要（可多版本） ── n 导出记录
模板 1 ── n 纪要
```

### 8.3 存储结构（首版 schema）

| 表 | 主键 | 关键字段 | 说明 |
|---|---|---|---|
| `schema_meta` | key | version, applied_at | 版本与迁移记录 |
| `projects` | id | root_path, name, last_opened_at | 项目根唯一 |

| `tool_calls` | id | session_id, turn_id, tool, args_digest, status, duration_ms | 参数摘要不存全文 |
| `approvals` | id | session_id, kind, payload, status, expires_at | kind ∈ permission/plan/goal |
| `artifacts` | id | session_id, kind, rel_path, sha256, size | 方案与导出制品 |
| `plugins` | id | version, enabled, granted_permissions, installed_at | 授权快照 |
| `skills` | id | scope, project_id, path, enabled | scope ∈ global/project |
| `mcp_servers` | id | name, transport, config_ref, status | 配置引用密钥库 |
| `meetings` | id | project_id, title, status, started_at, ended_at, duration_ms, template_id | 会议主表 |
| `meeting_audio_parts` | id | meeting_id, seq, rel_path, start_ms, end_ms, bytes, sha256 | 音频分片清单 |

索引要求：

1. 消息全文检索使用虚拟表（FTS），随写入增量更新。
2. `meetings(status)`、`meeting_transcripts(meeting_id, start_ms)`、`sessions(project_id, last_active_at)` 建复合索引。
3. 转写表按会议分区清理，删除会议须级联删除分片、转写、纪要、导出记录与文件。

```text
<项目根>/

│   └── meetings/<会议ID>/

│       ├── audio/part-0001.wav ...      音频分片
│       ├── transcript.jsonl             转写段（追加式）
│       └── minutes/v1.json, v1.docx     纪要版本与导出产物
└── 会议纪要/                            默认导出目录

<用户数据目录>/
├── db/index.db                          索引库
├── sessions/<会话ID>.jsonl               会话日志
├── models/asr/<模型标识>/                本地模型
├── models/voice/<模型标识>/
├── voiceprints/<档案ID>.bin             声纹向量
└── logs/
```

### 8.5 迁移与兼容

1. 每个版本只允许前进式迁移，不提供自动降级。
2. 迁移在事务内执行，失败回滚并保持旧版本可启动。
3. 迁移前自动备份索引库（保留最近两次）。
4. 禁止假设空库：所有查询须兼容历史字段缺失。
5. 删除字段须先停止读写一个版本周期，再物理移除。

### 8.6 检查点、恢复与一致性

| 场景 | 处理 |
|---|---|
| 应用崩溃 | 启动时扫描未结束轮次，状态置为「已中断」，不自动重放 |
| 会话日志损坏 | 逐行容错解析，跳过坏行并记录，保留可读部分 |
| 音频分片损坏 | 依据清单校验和判定，跳过损坏分片并提示 |
| 并发写入同一会话 | 由宿主层串行化，拒绝跨进程并发写 |
| 导出中断 | 临时文件残留由启动清理任务删除 |
| 时钟回拨 | 记录单调时间与墙钟时间两套，排序以单调时间为主 |

### 8.7 数据保留与清理

1. 会话默认永久保留，由用户手动删除；删除须同时清理日志、索引与制品。
2. 音频默认保留 90 天可配置，到期提醒后删除，不静默删除。
3. 声纹档案默认关闭，删除即物理清除，不留备份。
4. 日志按大小轮转，最多保留 7 天。

## 9. 接口设计

### 9.1 总览与命名

| 边界 | 形式 | 命名规范 |
|---|---|---|
| 渲染层 ↔ 编排层 | 预加载桥 IPC | `<域>:<动作>`，域与模块一一对应 |
| 编排层 ↔ 宿主层 | stdio JSON-RPC / NDJSON | `<域>.<动作>`，方法与数据域同名 |
| 宿主层 ↔ Agent 运行时 | stdio 消息 | `agent.<事件>` / `host.<请求>` |
| 插件 ↔ 宿主/运行时 | 受控桥 | 按贡献点命名空间隔离 |
| 外部 ↔ 本地控制面 | MCP 工具调用 | `pi_<域>_<动作>` |

硬性规则：所有跨边界结构在共享层以 schema 定义，运行时校验；未知字段须拒绝而非忽略。

### 9.2 渲染层 ↔ 编排层

| 通道域 | 主要动作 | 说明 |
|---|---|---|
| `project` | list/open/close/reveal | 路径由系统选择器产生，渲染层不得伪造 |
| `session` | create/list/switch/archive/branch/search/send/stop | 发送后由编排层返回轮次标识 |
| `turn` | queue/cancel/retry | 队列操作 |
| `approval` | respond/list | 响应必须携带请求标识与决策 |
| `plugin` | install/enable/disable/uninstall/grant | 安装路径受白名单约束 |
| `meeting` | start/pause/resume/stop/status/rename/speakers/regenerate/export | 会议全流程 |
| `audio` | deviceList/permission/level | 设备与电平，不含音频内容 |
| `model` | list/test/switch | 凭证不经过渲染层回传 |
| `update` | check/install/status | 不接受地址参数 |

安全约束：

1. 桥暴露的方法白名单固定，新增须评审。
2. 渲染层传入的路径、命令、URL 均视为不可信，宿主层重新校验。
3. 事件推送为单向，渲染层不得主动读取宿主状态。

### 9.3 编排层 ↔ 宿主层（首版 RPC）

| 方法域 | 代表方法 | 错误类型 |
|---|---|---|
| `workspace` | resolve、validatePath、list | `PATH_OUT_OF_SCOPE`、`PATH_FORBIDDEN` |
| `session` | create、get、updateMode、list、search | `SESSION_NOT_FOUND` |
| `turn` | begin、append、end、interrupt | `TURN_CONFLICT` |
| `tool` | read、write、delete、exec、search | `TOOL_TIMEOUT`、`TOOL_DENIED` |
| `permission` | evaluate、request、resolve | `PERMISSION_TIMEOUT`、`PERMISSION_DENIED` |
| `plan` | submit、pending、resolve | `PLAN_APPROVAL_TIMEOUT`、`PLAN_EXPIRED` |
| `secret` | get、set、delete（仅宿主内部路由） | `SECRET_UNAVAILABLE` |
| `plugin` | install、enable、disable、list | `MANIFEST_INVALID`、`PERMISSION_DENIED` |
| `meeting` | create、appendAudio、upsertTranscripts、setSpeakers、saveMinutes、exportDocx | `AUDIO_WRITE_FAILED`、`EXPORT_FAILED` |
| `voiceprint` | enroll、match、delete、list | `VOICEPRINT_DISABLED` |

协议约束：

1. 每帧一条 NDJSON，超长消息须分片并带序号。
2. 每个请求带唯一标识、方法名、参数、超时；响应必须回填同一标识。
3. 连接断开时所有未完成请求立即失败，不得无限等待。
4. 方法清单为白名单，未注册方法返回 `METHOD_NOT_FOUND` 并记审计。

### 9.4 宿主层 ↔ Agent 运行时

| 方向 | 消息 | 内容 |
|---|---|---|
| 运行时 → 宿主 | `host.tool.request` | 工具名、参数、会话标识、期望超时 |
| 宿主 → 运行时 | `host.tool.result` | 结果或错误码、截断标记、耗时 |
| 宿主 → 运行时 | `host.permission.request` | 需确认的操作描述 |
| 运行时 → 宿主 | `host.permission.answer` | 允许/拒绝 |
| 运行时 → 宿主 | `host.event` | 状态、用量、检查点 |

要求：工具调用必须携带会话标识，宿主据此解析项目根，**不得使用界面当前选中项目**。

### 9.5 事件与流式

| 事件 | 载荷 | 消费方 |
|---|---|---|
| `turn.started` | 会话、轮次 | UI |
| `message.delta` | 消息标识、增量文本或思考 | UI |
| `message.completed` | 完整消息引用 | UI、持久化 |
| `tool.started` / `tool.finished` | 工具、参数摘要、结果状态 | UI、审阅 |
| `approval.requested` / `resolved` | 审批标识、类型 | UI |
| `turn.ended` | 结束原因、用量 | UI、持久化 |
| `meeting.progress` | 阶段、百分比、当前分片 | UI |
| `meeting.transcript.appended` | 转写段 | UI（字幕） |
| `export.finished` | 路径、大小 | UI（提供打开入口） |

前端投影规则：渲染层仅投影当前生命周期内收到的事件；重载后只恢复「仍未终结」的状态，终态卡片不重建。

### 9.6 插件契约

清单首版字段：`schemaVersion`、`id`、`name`、`version`、`engines.host`、`contributes`、`permissions`、`main`。

权限标识（首版）：`tools`、`commands`、`skills`、`views`、`themes`、`services`、`mcp`、`subagents`、`files.read`、`files.write`、`shell`、`network`、`meeting.read`。

兼容承诺：同一主版本内新增权限与贡献点为向后兼容；删除或语义变更须提升主版本并提供迁移说明。

### 9.7 外部集成

| 集成 | 方向 | 要求 |
|---|---|---|
| MCP 客户端 | 出站 | 工具名加 `服务名.工具名` 前缀；连接失败退避重连；超时与结果大小受限 |
| 本地控制面 | 入站 | 默认关闭；仅回环；Bearer 凭证存于用户数据目录；危险操作须显式确认参数 |
| 远程控制 | 预留 | 传输中立契约，首版不实现；实现时不得暴露本地 RPC 与内部通道 |

### 9.8 会议模块专项接口

#### 9.8.1 ASR 引擎接口

| 项 | 定义 |
|---|---|
| 输入 | 音频字节、采样率、声道、语言、前置提示、词表、是否词级时间戳 |
| 输出 | 段数组（起止毫秒、文本、置信度）、耗时、模型标识、是否被截断 |
| 错误 | `MODEL_MISSING`、`MODEL_HASH_MISMATCH`、`AUDIO_DECODE_FAILED`、`INFERENCE_FAILED` |
| 约束 | 单次输入时长上限 5 分钟；超限由调用方切分 |

#### 9.8.2 说话人接口

| 项 | 定义 |
|---|---|
| 特征提取 | 输入语音段 → 输出归一化特征向量（维度由模型固定） |
| 会议内聚类 | 输入特征集合与人数上限 → 输出说话人分组 |
| 声纹匹配 | 输入特征与档案库 → 输出候选（档案标识、相似度、是否高置信） |
| 错误 | `VOICE_MODEL_MISSING`、`SEGMENT_TOO_SHORT` |

#### 9.8.3 纪要生成接口

| 项 | 定义 |
|---|---|
| 输入 | 会议标识、模板版本、转写版本、说话人映射、模型配置引用、生成选项（详略/语气/是否含附录） |
| 输出 | 结构化纪要（按模板字段）、章节溯源区间、用量、警告（字段缺失清单） |
| 约束 | 输出必须通过模板 schema 校验；校验失败时最多重试一次，仍失败则返回降级纪要 |

#### 9.8.4 导出接口

| 项 | 定义 |
|---|---|
| 输入 | 纪要标识与版本、样式模板、目标目录（受工作区约束）、是否附转写附录 |
| 输出 | 相对路径、字节数、耗时 |
| 约束 | 先写临时文件再原子重命名；同名自动加序号；路径越界直接拒绝并审计 |

## 10. 安全设计

### 10.1 威胁模型

| 资产 | 威胁 | 影响 |
|---|---|---|
| 用户代码与文件 | Agent 越界读写、路径穿越、符号链接逃逸 | 数据泄露或破坏 |
| 凭证与密钥 | 明文落盘、日志泄露、插件窃取 | 账号被盗用 |
| 执行权限 | 未授权命令执行、参数伪造绕过确认 | 主机被控制 |
| 会话与会议内容 | 未经授权被上传、被第三方读取 | 隐私泄露 |
| 扩展代码 | 恶意插件、越权调用 | 权限提升 |
| 更新链路 | 伪造更新源 | 供应链攻击 |

### 10.2 信任边界

| 区域 | 信任级别 | 措施 |
|---|---|---|
| 核心（外壳、宿主、运行时） | 可信 | 最小权限、审计、代码评审 |
| 插件与扩展 | 用户信任代码 | 权限声明、进程隔离、能力白名单、明确风险告知 |
| 模型输出 | 不可信输入 | 不直接执行、不直接作为路径、需经工具层校验 |
| 外部工具服务 | 不可信 | 结果按不可信数据处理，超时与大小限制 |
| 用户输入 | 不可信 | 路径、命令、URL 全部二次校验 |

**核心判定**：模型输出（包括工具参数）永不被信任为合法路径或命令；必须经宿主层策略求值。

### 10.3 最小权限落地

| 能力 | 限制 |
|---|---|
| 文件系统 | 仅项目根内；拦截系统目录、密钥目录、应用数据目录 |
| 命令执行 | 会话级权限模式 + 逐次确认；默认超时；工作目录限定 |
| 网络 | 仅模型端点与用户显式配置的 MCP 端点；无任意出站代理 |
| 浏览器/预览 | 仅本地产物；外部链接交由系统浏览器 |
| 剪贴板 | 读取须用户主动操作 |
| 凭证 | 仅宿主层可读，不返回渲染层，不写日志 |
| 麦克风 | 系统授权 + 应用内知情提示双闸门 |

### 10.4 工作区隔离

1. 每个会话绑定唯一项目根，由宿主层在轮次开始时解析，贯穿该轮全部工具调用。
2. 多标签切换不改变已绑定会话的项目根。
3. 跨项目操作被显式禁止，若需跨项目读取须用户显式授权并记录审计。

### 10.5 凭证保护

1. 凭证存于系统密钥库，索引库仅存引用标识。
2. 凭证不得出现在日志、崩溃报告、导出诊断包中。
3. 展示时脱敏（仅保留末四位）。
4. 删除 Provider 时同步删除对应凭证。

### 10.6 扩展与外部控制面风险控制

| 风险 | 控制 |
|---|---|
| 插件越权 | 能力集按授权发放；未授权调用拒绝并记录 |
| 插件拖垮主进程 | 独立进程 + 崩溃隔离 + 自动禁用异常插件 |
| 控制面被本机滥用 | 默认关闭、仅回环、随机凭证、危险操作须显式确认 |
| 扩展安装脚本 | 依赖安装仅限注册表来源，禁止执行第三方安装脚本 |

### 10.7 审计

审计范围：文件写入与删除、命令执行、权限判定结果、插件安装与授权变更、会议导出、声纹档案操作、凭证读写（仅记录动作，不记录值）。

审计记录保留 30 天，可按导出诊断包带走（脱敏）。

### 10.8 录音合规与音频隐私

1. 首次进入会议模块须阅读并确认知情提示；录制中界面常驻可见指示。
2. 产品文案须明确：**取得参会人同意是使用者的责任**。
3. 音频与转写默认仅本地存储；本版本不提供任何云端转写通道，从设计上杜绝音频外发。
4. 声纹功能默认关闭，启用须二次确认；档案删除为物理删除。
5. 导出文档默认不包含声纹与模型内部推理信息，仅含纪要正文与可选转写附录。
6. 会议数据随项目删除而删除，并提供独立的「清除全部会议数据」入口。

### 10.9 隐私总体承诺

| 项 | 承诺 |
|---|---|
| 遥测 | 不采集 |
| 账号 | 不要求注册 |
| 中转 | 无强制云端中转 |
| 模型请求 | 直达用户配置端点，内容处理取决于该服务商政策 |
| 本地数据 | 全部保留在用户设备，路径可查 |

## 11. 关键流程设计

### 11.1 启动与恢复

```text
外壳初始化（单实例检查）
 → 打开索引库并执行必要迁移（失败则进入只读安全模式）
 → 拉起宿主进程并握手（版本不匹配则拒绝继续）
 → 拉起 Agent 运行时并握手
 → 扫描未结束轮次与未完成审批 → 标记为「已中断」，不自动重放
 → 恢复上次窗口与会话 → 渲染首屏
 → 异步预热：模型列表、插件运行态、会议恢复扫描
```

失败处理：任一阶段失败须回滚已启动进程，向用户展示可操作错误（重试 / 查看日志 / 以安全模式启动）。

### 11.2 单轮对话与工具执行

```text
用户提交 Prompt
 → 编排层创建轮次 → 宿主写入轮次记录
 → 运行时组装上下文 → 调用模型（流式）
 → 增量事件推送渲染层
 → 收到工具请求：
     宿主解析会话项目根 → 路径校验 → 权限策略求值
     ├─ 允许 → 执行 → 结果回填
     ├─ 需确认 → 推送审批卡片 → 用户决策 → 允许则执行，拒绝则回填拒绝原因
     └─ 拒绝 → 回填拒绝原因，运行时决定替代路径或结束
 → 工具预算或停止条件达成 → 轮次结束 → 写入用量与检查点
```

关键约束：确认等待期间若用户关闭窗口，审批按超时策略拒绝；会话切换不影响已开始轮次的工具根。

### 11.3 方案审批

```text
Plan 模式 → Agent 调研 → 调用提交方案工具
 → 宿主将方案正文按原始字节写入不可变制品 → 记录摘要与结构化标题
 → 生成审批记录（含绝对超时）
 → 渲染层展示审批卡（可打开制品）
 → 用户批准：
     同一事务内：会话模式切为 Agent + 应用所选权限模式 + 入队执行轮次
     任何一步失败 → 整体回滚，不授予执行能力
 → 用户拒绝 / 超时 / 进程崩溃：
     审批置为终结态，不授予任何执行能力，会话保持 Plan
```

### 11.4 目标驱动

```text
用户定义目标与验收条件 → 冻结为契约
 → Agent 自行拆解与推进 → 每轮结束时对照验收条件自检
 → 未达成：继续；达成：提交结果与证据 → 用户确认
 → 用户中止：保留进度与结论
```

### 11.5 委派与并发

```text
主 Agent 调用委派工具 → 宿主校验并发配额
 → 创建子会话（继承项目/Provider/模型/权限模式）
 → 子 Agent 独立执行 → 结果结构化回传
 → 父任务取消 / 超时 / 会话关闭 → 级联取消子任务并清理
```

并发限制：单父会话上限与全局上限分别设限，超限时委派失败并告知 Agent 可重试。

### 11.6 插件生命周期

```text
安装：选择包 → 校验清单与签名（若有） → 展示权限 → 用户授权 → 解压至插件目录 → 登记
启用：加载入口 → 沙箱进程启动 → 注册贡献点 → 上报状态
运行：能力调用经受控桥 → 越权请求拒绝并审计
禁用：注销贡献点 → 清理定时器/监听/连接 → 结束进程
卸载：禁用 → 删除文件 → 清除授权与配置
异常：插件崩溃 → 自动重启一次 → 再失败则自动禁用并通知
```

### 11.7 异常与恢复

| 异常 | 处理 |
|---|---|
| 模型流中断 | 保留已产出内容，标记轮次不完整，提供续跑 |
| 宿主进程崩溃 | 编排层重启宿主，重建连接，未完成请求失败并告知 |
| 运行时进程崩溃 | 重启并重建会话上下文，从最近检查点继续 |
| 渲染层崩溃 | 重建窗口，按事件重放恢复可视状态 |
| 磁盘写满 | 中止录音与导出，保留已写数据并明确提示 |
| 设备被占用 | 提示占用方并允许重试或切换设备 |

### 11.8 会议纪要端到端流程

```text
① 进入会议纪要页 → 点击「开始记录」
    → 检查麦克风权限（无权限 → 引导系统设置）
    → 检查 ASR 模型（缺失 → 引导下载，可跳过先录音）
    → 创建会议记录（状态：准备中）

② 录制中
    → 采集麦克风 → 16kHz 单声道分帧
    → 电平与波形实时显示 → 每 5 分钟分片落盘
    → 静音切段 → 语音处理进程增量转写 → 字幕滚动
    → 每 30 秒更新心跳

③ 结束录制
    → flush 缓冲 → 写清单 → 状态置为处理中
    → 整段复算转写（替换增量结果）
    → 声纹提取 → 会议内聚类 → 生成说话人 S1..Sn
    → 若启用声纹库 → 自动匹配并标注置信度

④ 校正
    → 用户改名 / 合并 / 拆分说话人 → 全文同步
    → 用户可直接编辑转写文本

⑤ 生成纪要
    → 选择模板 → 触发总结（复用当前模型配置）
    → 分块归纳 → 汇总 → 结构化输出 → 校验
    → 章节溯源可点击跳转原文
    → 字段缺失清单提示用户补充

⑥ 编辑与定稿
    → 局部重写 / 重新生成 → 对比后采用 → 定稿生成版本

⑦ 导出
    → 选择样式与是否附转写附录 → 宿主生成 docx
    → 临时文件 → 校验 → 原子重命名 → 记录导出 → 提供打开目录入口
```

降级路径：

| 故障 | 降级 |
|---|---|
| ASR 模型缺失 | 仅录音，会后补装模型再处理 |
| 模型服务不可用 | 输出纯转写纪要（含说话人分段），仍可导出 |
| 设备中途断开 | 自动切换默认设备，缺口在时间轴上标记 |
| 磁盘不足 | 提醒并停止录制，保留已有分片 |

### 11.9 更新流程

```text
启动后延迟检查 → 有新版本则提示 → 用户确认下载 → 下载并校验
 → 支持应用内安装的平台：安装并重启
 → 其他平台：跳转下载页
 → 失败：保留当前版本，记录日志，不阻塞使用
```

### 12.2 迭代节奏

- 双周一个迭代，每个迭代结束须有可运行版本。
- 每个里程碑结束执行一次完整回归与三平台冒烟。
- 阶段二（M6–M8）可与 M4/M5 部分并行，但不得早于 M3 完成。

### 12.3 并行开发约束

1. 一个任务一个分支、一个独立工作目录，禁止在主分支直接开发。
2. 分支命名 `<类型>/<简短描述>`，类型限 feat/fix/docs/test/chore/refactor/perf/build/ci。
3. 同一文件的多任务改动须显式协调，避免合并冲突积累。
4. 交付顺序固定：分支实现 → 合并本地主干 → 在主干跑相关端到端 → 提审 → 合并远端 → 清理分支。

## 13. 测试与验收

### 13.1 测试分层

| 层 | 范围 | 要求 |
|---|---|---|
| 单元 | 纯函数、状态机、协议编解码、模板校验 | 核心逻辑覆盖，禁止依赖真实网络 |
| 集成 | RPC 方法、权限策略、持久化与迁移、ASR 管线（小样本） | 使用临时目录与夹具数据 |
| 端到端 | 关键用户旅程（见 3.14 用例） | 真实进程，可自动化者自动化 |
| 人工验收 | 交互手感、导出文档观感、噪声环境转写 | 验收清单逐项签核 |

### 13.2 端到端场景编号

采用语义化标识：`E2E-<域>-<行为描述>`，例如：

```text
E2E-SESSION-switch-does-not-show-stale-transcript
E2E-PLAN-approval-survives-renderer-reload
E2E-TOOL-path-outside-workspace-is-rejected
E2E-PLUGIN-disable-cleans-runtime
E2E-MEETING-crash-during-record-keeps-audio
E2E-MEETING-export-docx-opens-in-office
E2E-MEETING-summary-never-invents-attendees
```

规则：一经合并即视为稳定标识，不重排、不复用；新增前先检索是否已有等价场景。

### 13.3 验收标准

| 需求域 | 验收判定 |
|---|---|
| SHELL | 三平台均可启动、恢复窗口状态、命令面板可执行全部注册命令 |
| SESS | 会话可创建/切换/分支/检索，长会话滚动流畅 |
| MODE | Plan 未经批准无任何写操作；批准后自动执行 |
| PROV | 三类端点均可完成一次对话；凭证不落明文 |
| TOOL | 越界路径 100% 拒绝；确认超时按拒绝处理 |
| SUB | 父取消后子任务 5 秒内终止 |
| EXT | 插件越权调用被拒并审计；卸载后无残留进程 |
| MTG | 见下表专项验收 |
| SYS | 强杀进程后重启，已落盘数据可恢复且不重放 |

会议模块专项验收：

| 项 | 判定 |
|---|---|
| 录制完整性 | 1 小时会议分片齐全、总时长误差 ≤ 2 秒 |
| 转写质量 | 安静环境字错率 ≤ 15%，噪声环境 ≤ 30% |
| 实时性 | 语音结束至字幕出现 ≤ 5 秒（8 核 CPU、均衡档模型） |
| 说话人 | 3 人会议分离错误率 ≤ 25%，人工校正后全文一致 |
| 声纹 | 误接受率 ≤ 5%，删除档案后不可再匹配 |
| 纪要质量 | 无编造人名与数字；待办项均可溯源到原文 |
| 导出 | docx 在 Word 与 WPS 打开样式正确，页码与页眉完整 |
| 恢复 | 录制中强杀进程，重启后可继续处理已有分片 |
| 隐私 | 抓包确认无音频外发 |

### 13.4 质量门禁

合并前必须全部通过：

1. 构建成功、类型检查零错误。
2. 静态检查（格式与规则）零告警新增。
3. 相关单元与集成测试通过。
4. 变更涉及的端到端场景在主干上通过。
5. 数据变更附带迁移与兼容验证。
6. 无凭证明文、无本地绝对路径、无调试残留。

任一未通过不得合并；未执行的检查不得记为通过，须标注未执行原因与残余风险。

### 13.5 缺陷分级

| 级别 | 定义 | 处理 |
|---|---|---|
| S1 | 数据丢失、凭证泄露、越权执行 | 立即阻断发布，当日修复 |
| S2 | 主要功能不可用、崩溃 | 本迭代内修复 |
| S3 | 次要功能异常、体验缺陷 | 排期修复 |
| S4 | 文案、样式、优化建议 | 合并处理 |

## 14. 发布与运维规划

### 14.1 产物矩阵

| 平台 | 架构 | 形态 |
|---|---|---|
| Windows | x64 | 安装包、便携单文件 |
| macOS | arm64 / x64 | 磁盘映像、压缩包 |
| Linux | x64 | AppImage、deb、rpm |

### 14.2 签名与合规

1. Windows 使用代码签名证书，避免 SmartScreen 拦截。
2. macOS 使用开发者证书签名并公证；未签名构建须提供明确的安全提示说明。
3. 三方依赖许可证清单随发布归档。
4. 声明最低系统要求（含 Linux glibc 下限）并在启动时校验。

### 14.3 升级与回滚

1. 升级前保留上一版本可执行文件，支持回滚。
2. 数据库迁移失败时回滚并保持旧版本可用。
3. 升级不得删除用户数据目录中的会议音频与声纹档案。
4. 大版本升级提示变更影响与不可逆项。

### 14.4 诊断与支持

| 能力 | 说明 |
|---|---|
| 日志 | 本地分级日志，按大小轮转，默认保留 7 天 |
| 诊断包 | 一键导出环境、版本、配置摘要、最近日志（脱敏） |
| 会议诊断 | 导出转写耗时、模型档位、分片完整性报告（不含音频内容） |
| 崩溃上报 | 默认不上传；用户可手动导出 |

### 14.5 版本节奏

`主版本.次版本.修订号`。主版本含不兼容变更；次版本含新功能；修订号仅修缺陷。每季度至少一次次版本发布。
