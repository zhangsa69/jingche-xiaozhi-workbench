## 4. 运行分层与边界

```
① 渲染层  apps/desktop/src            React，只做界面与交互
        │  window.pi.*（preload 暴露的白名单）
        ▼
② 桥      electron/preload            通道名写死；新增能力必须同时改主进程注册
        ▼
③ 主进程  electron/main               薄编排：开窗、IPC 分发、更新、计费
        │  stdio JSON-RPC
        ▼
④ 数据内核 crates/host-core           唯一能碰 SQLite 的进程
        │
        ▼
⑤ 智能体  agent-host（编排）+ agent-runtime（模型与工具）
        │  HTTPS / 内网 HTTP
        ▼
⑥ 管控中心 apps/control-plane         账号、额度、网关、审计
```

**硬边界**（违反即回退）：

- 渲染层**不得**直接访问 SQLite、文件系统、shell；一律经 preload。
- 渲染层**不得** import `electron/main` 的实现细节；跨层只走 `packages/shared` 的契约类型。
- SQLite 只由 `host-core` 拥有；主进程也不行。
- 智能体执行**不得**搬进渲染层。
- `packages/*` **不得**依赖 `apps/*`（共享包只能被依赖）。

## 5. 增量开发从哪开始

### 5.1 标准做法

```powershell
cd 'E:\京车小智工作台\jingche-xiaozhi-workbench'
git switch main
git pull --ff-only          # 远端已同步时可跳过
git switch -c feat/短描述   # 例：feat/plugin-market-filter
```

在 `control-plane-wt` 里也能开新分支（它现在和 main 同头）：

```powershell
cd 'E:\京车小智工作台\control-plane-wt'
git switch -c fix/短描述 main
```

### 5.2 不要做的事

- ❌ 在 `main` 上直接提交（先拉分支）。
- ❌ 往 `feat/control-plane` 上再提交——它和 main 同头，一提交就产生新分叉。
- ❌ 复用一个已经完成使命的工作树当"长期开发目录"。
- ❌ 把 `release/`、`out/`、`target/`、`.codebuddy/` 提交进库。

## 6. 代码规范

### 6.1 通用

- 标识符、注释、提交信息、规格、ADR 一律**英文**；面向用户的中文只出现在 `packages/i18n` 文案里。
- 不用 `any` / `as any` / `@ts-ignore` / `@ts-nocheck` 来"先跑通"。类型确实表达不了时，用精确的联合类型或 `unknown` + 收窄。
- 不吞异常：`catch` 里要么处理，要么带上上下文抛出。空 catch 属于缺陷。
- 新文件规模：TS/TSX 建议 < 500 行，Rust < 700 行；到 800/1000 行必须重新划分职责。
- 不做顺手重构：一个提交只解决一件事；格式化单独提交会污染 review。

### 6.2 渲染层（React + Zustand）

| 内容 | 放哪 |
|---|---|
| 纯状态 | `src/stores/*`（zustand） |
| 多步流程 | `src/services/*` 或 hook，不要塞进 store |
| 纯变换 | 独立 reducer / 纯函数，便于测试 |
| 组件 | 只负责渲染 + 交互接线 + 局部 UI 状态 |

- 组件里禁止直接调 `window.pi.*` 之外的副作用；调用集中到 service。
- 每个 `await` 之后都要假设"状态可能已经变了"（会话切换、渲染层 reload）。

### 6.3 主进程

- 保持"薄编排"：业务规则放 `packages/*` 或 `host-core`，主进程只做编排与进程级副作用。
- 新增 IPC 必须三件套同时改：`preload` 白名单、main 的 handler、`packages/shared` 的类型。
- 长生命周期资源（监听器、定时器、子进程、sidecar、WebSocket）必须有明确 owner 与清理路径，覆盖 reload / 退出 / 禁用。
- 不要在主进程里拼 SQL，也不要直接读用户数据库文件。

### 6.4 共享契约（`packages/shared`）

- `protocol.ts` 是唯一真相：`PROTOCOL_VERSION`、`APP_NAME`、`APP_VERSION` 都在这里。
- 改协议 = 升 `PROTOCOL_VERSION` + 更新 `docs/spec` + 想清楚旧客户端怎么办（向后兼容优先）。
- 判定"公网 / 内网"统一用 `isPublicHostname`（ADR 0247 语义），不要在别处再写一套正则。

### 6.5 Rust（`crates/host-core`、`apps/control-plane`）

- 模块按职责切：db / 迁移 / repository / 领域逻辑 / 文件系统，不要混在一个 `db.rs` 里继续加。
- 迁移只增不改；每次 schema 变更都要升 schema 版本并补测试。
- 外部失败路径不用 `unwrap()` / `expect()`；内部不变量可以用，但要写清为什么成立。
- 提交前：`cargo fmt --check`、`cargo clippy -p <crate> --all-targets`、`cargo test -p <crate> --locked`。
- `Cargo.lock` 随版本号一起变，`--locked` 必须能过。

### 6.6 管控中心（`apps/control-plane`）

- handler 保持薄：解析请求 → 调 service → 返回；SQL 只在 repository 层。
- 所有跨租户查询必须带租户/账号条件；审计日志与业务写入同事务。
- 管理前端（`web/`）是独立版本线，不要跟着客户端版本号走。

### 6.7 插件

- `plugin-sdk` 契约默认向后兼容；破坏性变更必须走 ADR 并在 `docs/spec/07-plugins/` 同步。
- 新增权限要同时改权限矩阵文档与运行时校验，不能只改文档。

## 7. 品牌、文案与更新说明

- 产品名**永远**从 `APP_NAME`（`packages/shared/src/protocol.ts`）来。写死 `"PI-Desktop"` 或 `"京车小智工作台"` 都是缺陷——启动冒烟就因此红过。
- 用户可见文案进 `packages/i18n`，8 个语言目录键集合必须一致。
- 内置更新说明在 `packages/shared/src/changelog*.ts`：**8 个目录的版本集合与高亮条数必须完全一致**，否则 `changelog.test.ts` 与 `check:release-docs` 会红。
- 当前 1.0.0 条目：中文（简/繁）为正式撰写，`de/es/fr/ko/tr` 暂时复用英文原文并在文件内注明待翻译。

## 8. 网络与安全红线

- 渲染层不碰凭证；令牌只在主进程与 `host-core` 之间流转。
- 不为了"先能用"而放宽权限校验、沙箱边界、URL 校验、文件系统限制。
- 访问外网前先判断部署形态：内网部署（私有 IP / `localhost` / `.local` / `.internal`）不得发起 GitHub 更新检查，判定统一走 `isPublicHostname`。
- 日志里不得出现令牌、验证码、密码、完整请求体。

## 9. 测试要求

改哪跑哪，别只跑一个就宣布完成：

| 改动面 | 必跑 |
|---|---|
| 任意 TS 改动 | `pnpm --filter @pi-desktop/desktop typecheck` + 相关包 `test` |
| 渲染层 / 主进程行为 | `pnpm --filter @pi-desktop/desktop test`（2375+ 用例，约 15 秒） |
| Rust | `cargo test -p host-core --locked` / `-p control-plane --locked` |
| 文档 / 规格 | `pnpm docs:check` |
| 版本号 / changelog / README | `pnpm check:release-docs` |
| 启动路径、IPC、窗口、单实例 | `pnpm test:e2e:boot` |
| 登录、额度、网关 | `pnpm test:e2e:control-plane` |

约定：

- 能写成"源码契约测试"的，就照 `apps/desktop/test/*.test.mjs` 的写法（读源码 → 正则断言关键调用存在），成本低、防回归有效。
- 新 E2E 用语义 ID：`E2E-<DOMAIN>-<slug>`；**不要**再新增 `E2E-123` 这类全局序号（已有的是冻结的历史 ID）。
- 不通过删测试、跳测试、放宽断言来让流水线变绿；先分类（产品回归 / 测试回归 / 环境 / 基础设施 / flaky）。

## 10. 提交与发布

### 10.1 提交

- Conventional Commits：`feat|fix|docs|test|chore|refactor|perf|build|ci(scope): subject`，英文。
- 一个提交一个逻辑关切；提交前看一遍完整 diff，清掉调试日志、临时开关、无关格式化。
- 合并进 main 前，在**集成了改动的代码**上跑对应 E2E。

### 10.2 发布（1.0.x 线）

升版本要一次改完这 14 个面，漏一个就 `check:release-docs` 红：

```
package.json · apps/desktop/package.json · packages/{shared,i18n,agent-runtime,agent-host,plugin-sdk,plugin-devkit}/package.json
docs/package.json · Cargo.toml(workspace) · Cargo.lock(2 处)
packages/shared/src/protocol.ts(APP_VERSION) · README.md · README.zh-CN.md
```

外加：`changelog*.ts` 8 个目录加同一版本条目（条数一致）、`changelog.test.ts` 固定最新版本、README 里保留 `1.0.x` 版本线字样。

### 10.3 发布动作与禁忌

- 打 tag：`git tag -a vX.Y.Z -m "..."`。
- **推 tag 会触发 GitHub Actions 全平台发布**。只想本地出包时，tag 留本地不推。
- 本地出 Windows 包：`pnpm --filter @pi-desktop/desktop dist:win`（必须先设代理，见 §12）。
- 不要 force-push `main`，不要改写已推送的历史。

## 12. 这台机器的已知环境坑

| 坑 | 现象 | 处理 |
|---|---|---|
| git 代理配置失效 | 配置写 `127.0.0.1:10808`，实际 Clash 在 `7890` | 临时覆盖：`git -c http.proxy=http://127.0.0.1:7890 -c https.proxy=http://127.0.0.1:7890 push`；不要擅自改 git 配置 |
| 直连 GitHub | TCP 通，TLS 返回 `Empty reply from server` | 必须走代理 |
| electron-builder 下载 | 不带代理会卡 600 秒超时 | 先 `$env:HTTP_PROXY='http://127.0.0.1:7890'; $env:HTTPS_PROXY=$env:HTTP_PROXY` 再打包 |
| `vitepress build` | 删除 `.vitepress/dist`（1296 文件）被环境守卫拦下 | 属环境限制；用 `pnpm docs:check` 做内容校验 |
| PowerShell 传参 | `pnpm --filter '@x^...'` 里的单引号会被 cmd 当字面量 | 改用多次 `--filter` 或 `pnpm --filter <pkg> build`（不带脚本内引号） |
| 中文输出乱码 | 控制台按 GBK 解码 | 读文件用编辑器/tool，不要用控制台看中文内容 |

## 13. 红线清单（Don't）

1. 不在 `main` 上直接开发，不往 `feat/control-plane` 继续提交。
2. 不硬编码产品名、版本号、E2E 全局序号。
3. 不让渲染层碰 SQLite / 文件系统 / shell。
4. 不为过测试而删测试、跳测试、放宽断言。
5. 不在日志或提交里出现令牌、密码、内网口令。
6. 不把 `release/`、`out/`、`target/`、`.codebuddy/`、`*.docx` 提交进库。
7. 不推 tag（除非明确要发版）、不 force-push。
8. 不擅自改 `git config`、不改动别人的分支或工作树。
